Native WAVE player and bounded PCM output

Wave, Player, AudioSDK and AudioDevice are Lean-authored guest modules. The parser reads actual verified ContentSDK ranges, checks the file, converts mono samples when necessary and submits decoded samples. The host adapter receives already decoded stereo samples. It never opens the WAV, chooses content or implements the player. Personal playback content stays in volatile guest RAM unless a separate trusted Objects-vault approval retains it.

Exact supported format and controls

The initial format is RIFF/WAVE, PCM encoding1, signed16-bit little-endian, 48000Hz, one or two channels. Other codecs, rates, widths, channel counts and extensible-WAVE encodings reject. Checked RIFF lengths must match the scoped content length. At most128 chunks are scanned. Unknown chunks skip with their required odd-byte padding. Duplicate format/data chunks, truncated sizes, inconsistent byte rate/block alignment and partial frames reject. Range reads are at most512bytes and split at authenticated4096byte content boundaries. Seeking changes the requested position without allocating or reading the whole file.

Library H binds an already approved audio player and Space attaches the selected ready item. Alt-Tab selects the player; Space plays, pauses or resumes. S stops. Left/Right seek five seconds within the decoded duration. The interface reports actual accepted-frame position, duration, buffering, device unavailable/owned, malformed format and end. Position is device acceptance, not a speaker clock. Playback uses one1024byte decoded output block. Stop or seek resets the owned output epoch before reusing buffers.

Device and authority boundary

PCM2 is an explicitly selected modern virtio-serial byte transport at MMIO0x10008000, slot7, device ID3; it is separate from networking. It negotiates VERSION_1 and MULTIPORT, binds non-console port1 named lt-pcm1, and transmits stereo S16LE48000 frames through queue5. One descriptor with at most1024bytes and length divisible by4 may be outstanding. The QEMU adapter binds virtio-serial-device,max_ports=2,bus=virtio-mmio-bus.7 and virtserialport,nr=1,name=lt-pcm1 to an explicit socket chardev. Both assembly emulators preserve incomplete descriptors on nonblocking raw-output backpressure. Neither device nor adapter decodes WAV or implements virtio-sound.

Control receive/transmit queues2/3 contain eight bounded descriptors. The guest sends DEVICE_READY, checks the selected PORT_ADD and exact port name, sends PORT_READY, observes host PORT_OPEN, then sends its own PORT_OPEN. Acquisition fails if the selected relationship is unavailable or malformed. Runtime inspection consumes at most eight control messages and observes host closure. Device reset acknowledgement precedes wiping previous control/data rings and private buffers; owner/epoch checks remain independent of port identity.

Earlier PCM1 images use console port0/queue1 and remain runnable through explicit image-version selection. That QEMU console endpoint is unsuitable for lossless playback under backpressure: QEMU console short-write handling can discard bytes while completing a descriptor, whereas its non-console port throttles and retries. The live PipeWire trial exposed an internal4096byte omission followed by the exact ending; a separate raw-adapter probe preserved all supplied bytes. PCM2 addresses that transport distinction. Earlier PCM1 capture results remain historical evidence, not a guarantee under a blocked speaker sink.

The upstream assumptions were checked against OASIS Virtio1.2 (modern MMIO transport, console transmit queue and reset) and QEMU invocation documentation (virtconsole/socket character backend). A running reference QEMU device tree confirmed slot7's address. These sources specify transport behavior; the decoded PCM convention is this project's explicit adapter contract.

Audio DMA state0x80e26000, output queue0x80e28000 and buffer0x80e2a000 are disjoint from network, display, block and guarded process mappings. PCM2 adds control rings0x80e2c000–0x80e2ffff and bounded control buffers0x80e30000–0x80e30407. The development machine now has160MiB on QEMU and both interpreters. Natural end waits for the last owned transmit descriptor to complete before resetting output. Explicit stop/seek cancel that epoch and clear decoded/range scratch. The host cannot retract samples it has already accepted. ARM interpreter startup uses a bounded300second launcher deadline; other backends default to60seconds. --startup-timeout selects an explicit1–600second transport readiness limit without changing guest job deadlines.

Running and verifying output

./lt app --profile 2 --module Guest.Player --entry Guest.Player.main --name player
./lt run --socket /tmp/personal.sock --graphics /tmp/personal.qmp --network-mux --pcm-play
# Deterministic explicit capture instead of speakers (new file, mode0600):
./lt run --socket /tmp/personal.sock --graphics /tmp/personal.qmp --pcm-sink /tmp/personal.pcm
# Supply --backend x86_64 or --backend aarch64 for the same guest image.
python3 tests/player_audio.py --backend qemu --player PLAYER.ltrel --public PUBLISHER.pub --output build/player-check
python3 tests/audio_device.py --backend qemu --output build/audio-boundary-check
# Deliberately blocked raw test sink; no physical-speaker claim:
python3 tests/audio_backpressure.py --backend qemu --image IMAGE --package AUDIO_PROBE.ltrel --public PUBLISHER.pub --output build/audio-backpressure

--pcm-play selects aplay when installed, otherwise pw-cat --playback --raw --format s16 --rate 48000 --channels 2 --channel-map stereo -. The PipeWire fallback needs a running server and playback endpoint. Its s16 format is native-endian, so this adapter permits it only on a little-endian host; it performs no host sample conversion. The exact flags were checked against installed pw-cat 1.4.9 help, the official pw-cat manual and its format mapping. Raw mode receives the guest's decoded samples directly; it does not ask the host to decode WAV.

--pcm-sink is an explicitly requested diagnostic export, not a personal download directory. Neither captures unless requested. Samples are signed little-endian stereo at48000Hz,192000bytes/second. When --pcm-sink and --pcm-play are combined, capture records each complete block only after every byte was accepted by the raw child pipe. A blocked or interrupted child write cannot advance the capture by that block. This acknowledges pipe delivery, not child consumption or physical speaker drain; capture-only behavior is unchanged. The adapter exposes the selected sink name, child exit status and error. An unexpected child exit closes its sample socket, and shutdown bounds its waits before terminating and reaping an unresponsive child. Focused subprocess checks verified exact raw-byte forwarding, early exit, backpressure and cleanup; they did not exercise a guest or speakers. Raw captures alone do not establish audible output.
