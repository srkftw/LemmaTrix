Indexed retained content

Guest.IndexedContent extends the existing guest content interfaces with sixteen independent item slots per explicitly selected storage purpose. Retaining B in a different slot preserves A. An item can contain up to 64 MiB under ContentManifest version 2; the ordinary volatile pool remains 1,472 pages (6,029,312 bytes) shared by four roots. Backed roots occupy separate bounded metadata slots and consume no resident payload pages. ContentManifest version 1 retains its original limit and audio-only declaration. Version 2 explicitly declares PCM WAVE or generic artifacts; a generic artifact is never admitted to the WAVE decoder merely because it has a valid commitment.

Purpose 1 is the approved, unlocked, encrypted personal Objects vault. Purpose 2 is intentional unencrypted operator storage. These are different device bindings and namespaces. No store is created, enlarged, mounted, decrypted or selected implicitly. Without approved storage, the original bounded volatile behavior remains available. A manifest commitment supplies neither retention approval nor read, network or execution authority.

Nonresident opening and reads

Opening authenticates a fixed 4,096-byte index containing the canonical manifest, manifest commitment, scoped provider/federation references, namespace, immutable operation/budget, availability bitmap and optional 1,536-byte signed consumer/admission selection. It creates fresh incarnation-bound content grants. Opening and inventory enumeration read metadata only. They do not allocate, read or reimport the entire payload.

The existing ContentSDK.describe, read, proof, share and release work for backed roots. The content compartment resolves its opaque locator through the Vault compartment. Vault owns all block access and personal keys. A requested chunk is decrypted where applicable, its exact index/length and canonical padding are checked, and its raw SHA-256 and positional Merkle path are verified against the committed manifest before any range is returned. One verified 4,096-byte chunk is cached. The cache binds a current scoped session and chunk index; it is not a content-global deduplication oracle. The index, staging record and verification scratch are also bounded. Large payloads are absent from Project records and application arenas.

State 1 means verified partial availability; state 2 means all chunks have been committed and complete publication has flushed. Missing verified bytes return status 6. Corrupted chunks/indexes return status 5, rather than buffering forever. An exact content read grant may register one pending chunk, with a bounded readiness notification after that root generation commits the chunk. A separately reopened root may use the player's bounded buffering wait. Possession of partial bytes does not admit an executable closure or advertise a complete seed.

All format lengths, chunk counts, slot/bank indices and arithmetic are validated before I/O. A reserve selects an unused alternate bank and an immutable generation. Chunk commit writes the record, authenticated availability index and explicit flush before publishing the alternate checkpoint root and flushing it. Complete publication is a separate authenticated transition. Previous complete banks remain available during preparation; existing readers retain their immutable generation. An exact expected-manifest open can select the preceding committed bank while another manifest is prepared.

A completed item can be deleted while an authorized reader is active: a flushed tombstone removes it from future inventory/opening while the immutable reader remains usable. Its bank is unavailable for reuse while the reader's exact content-compartment incarnation retains it. After references are released, explicit collection and a subsequent deletion/reuse reclaim its logical allocation. Dead compartment incarnations do not pin banks forever. Logical deletion does not claim physical secure erasure or deletion of copies held by other nodes.

Personal index and chunk records use a domain-separated key derived from the approved Objects key. Nonces are reserved as a complete transaction interval in alternating authenticated high-water records; reservation flushes before encryption. Each immutable chunk and each index checkpoint has a different nonce. Corrupted nonzero allocator records fail closed. AEAD binds the intended format, namespace, content commitment, generation, position and length. Older indexed roots carrying an additional ciphertext SHA-256 remain readable; current roots can bind the index's authenticated tag directly. This does not establish freshness against malicious rollback of the complete store and its allocator. Continuing encrypted writes after adversarial allocator rollback requires a fresh store/key; protection against that rollback is not implemented.

The operator path uses the same manifest/Merkle validation with intentional plaintext storage. Redundant public chunk checksums are unnecessary: authenticated raw bytes and their positional Merkle proof are checked on every uncached read. A trusted content-compartment commit can reuse its already completed guest validation; an opaque block import always performs full guest validation. No host tool installs an authoritative index.

Native interfaces

Guest.IndexedSDK exposes the selected management portal. Requests use the standard eight-word header; all handles are live grants and must not be serialized as authority. A fresh permit binds the exact live recipient, purpose, slot, namespace, expected manifest and byte ceiling. Issuance requires the trusted administrator; personal permits additionally require the approved Objects unlock.

Explicit large imports and migration

IndexedImport extends the content/import job path for large initially authorized files. An operator can deliberately export one selected file and its untrusted proofs into a named operator input extent beyond the indexed banks. The tool requires an affirmative plaintext operator-input export flag and an explicitly provisioned store with no earlier input extent. This is public/operator input staging, never an undisclosed plaintext personal cache. The destination can be the separately approved encrypted personal store. The guest validates every actual input chunk and commits its own directory and encryption; host records and checksums do not become authority. A restart can resume the same persisted input extent, manifest, operation and checkpoint under a fresh approved permit. The compiler and untrusted jobs receive no storage keys.

./lt server-store init /explicit/operator.img --indexed
./lt indexed-import stage --operator-store /explicit/operator.img \
  --input /explicit/authorized.wav --descriptor /explicit/input.json --format wave \
  --approve-plaintext-operator-input-export
./lt run --backend qemu --socket /tmp/lt.sock --server-store /explicit/operator.img
# Obtain a fresh exact recipient/purpose/namespace/manifest permit with lt inventory permit.
./lt indexed-import submit --socket /tmp/lt.sock --grant PERMIT --operation OPERATION \
  --descriptor /explicit/input.json --provider PROVIDER_SHA256 --federation FEDERATION_SHA256
./lt indexed-import inspect --socket /tmp/lt.sock --operation OPERATION

The original selected-content vault formats and four operator archive slots remain readable. To migrate, explicitly recover the old selected root with its existing approval path, issue a new exact indexed permit and run ./lt indexed-migrate with the approved old content scope, optional selected metadata scope and new destination permit. It relays bounded existing range/proof RPCs into the ordinary guest validator and new transaction. The old committed backing and existing save regions remain intact before and after the new commit; there is no silent reformat or namespace merger. If migration is interrupted, recover the old selection normally or resume the same new operation under fresh authority.

Scope and evidence

These interfaces provide bounded independent retained items, authenticated direct ranges and recoverable import checkpoints. They do not supply arbitrary media decoders, malicious whole-store rollback detection, physical drive assurances, unlimited inventory, independent administration, paid settlement or anonymity. Current mode 3 exposes endpoints and traffic patterns. The campaign record identifies each actually exercised image and content digest; implementation descriptions here are not substitute execution evidence.
