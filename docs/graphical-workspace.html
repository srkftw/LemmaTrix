Native graphical creator workspace

Campaign 003 extends the existing live development implementation. Guest rendering, input policy, editing, graph validation, build-job binding, release authentication and encrypted storage execute as freestanding Lean/RV64. This remains an LT development profile, not completed LT-Machine-v1 conformance or the complete v0.2 MVP.

Build and start

./lt setup
./lt doctor
./lt build
# A from-source verification build is available as ./lt build --clean.
./lt emulators
./lt run --backend qemu --socket /tmp/lt.sock --graphics /tmp/lt.qmp --display gtk
# Assembly backends use a raw pixel file and ephemeral input FIFO:
./lt run --backend x86_64 --socket /tmp/lt.sock --graphics /tmp/lt-display
# In another terminal, with a Python installation containing Tk:
./lt display --graphics /tmp/lt-display
# ARM64 assembly on an x86 host:
./lt run --backend aarch64 --socket /tmp/lt.sock --graphics /tmp/lt-display

The QEMU graphics endpoint is QMP. A headless device client is available in tests/graphical_devices.py; it sends hardware input and reads pixels. QEMU can also present its scanout through an explicitly selected display adapter. UART remains a separate management/recovery interface. The assembly presenter transports pixels and raw events and implements no widgets, editor, approvals or project semantics.

The editor supports eight working files, each at most 32 KiB; graph members may be 64 KiB. Names are canonical bounded ASCII relative paths. Payload bytes preserve UTF-8, navigation/deletion avoid continuation-byte boundaries, and non-ASCII glyphs have a limited fallback renderer. ASCII upper/lowercase are distinct. The viewport shows 78 source columns and 25 lines; long lines remain intact but there is no horizontal viewport yet. Keyboard entry is the documented ASCII scan-code subset. This is a bounded editor with one undo snapshot, not the complete Lean language-server IDE or professional Unicode shaping. Dirty working memory, immutable session commits and an acknowledged encrypted snapshot are different states.

Project import and exact build

./lt project --socket /tmp/lt.sock import examples/creator --name creator
./lt project --socket /tmp/lt.sock list
# Editor: Shift-F2, choose creator, Enter; F3 selects Util.lean.
# Provision the chosen publisher once for this current session:
./lt ctl --socket /tmp/lt.sock trust --project creator --public build/publisher.pub
# Persistent disclosed bootstrap worker, in another terminal:
./lt project --socket /tmp/lt.sock serve --project creator \
 --sign-key build/publisher.pem --version 1.0.0 --output build/creator-worker
# Native editor: F4 commit, F5 build; diagnostics appear in the editor.
# Success is staged by the worker; F12 reviews its exact authority, Enter runs.
# The worker never auto-trusts or approves. Ctrl-C stops it.

# Alternatively use the one-shot explicit bootstrap boundaries after F5:
./lt project --socket /tmp/lt.sock build --output build/creator-job
./lt project --socket /tmp/lt.sock publish build/creator-job/job.result.json \
 --sign-key build/publisher.pem --name creator --version 1.0.0 \
 --rights 768 --output build/creator-1.ltrel
./lt ctl --socket /tmp/lt.sock trust --project creator --public build/publisher.pub
./lt ctl --socket /tmp/lt.sock inspect build/creator-1.ltrel
# F12 then Enter: local exact approval, installation, and native execution.

The fixed recipe is module Main, entry Main.main, resource profile 2. Lean elaboration, executable metaprograms, backend generation, assembler and linker run inside the OS-enforced build sandbox. Only the frozen project and approved SDK/toolchain closure enter it. The guest binds a completion to the job, current service incarnation, frozen source, profile and precommitted compiler identity. Build/Evidence records remain attached to that source even when the editor advances. Correctness of source-to-binary translation is an explicit builder assertion, not a guest proof.

The creator sample is a real multi-module application with over 64 KiB of UTF-8 resources. Resource files participate in elaboration inside the sandbox. Its independent native computation accepts keyboard input: changing Util.Weight from 3 to 7 changes the score for cat123 from 20 to 24. Publishing imports actual source, Build, Evidence, binary chunks and Release material into the typed guest graph. Manifest/source/evidence/license and binary commitments are checked. Guest validation reconstructs canonical source metadata from actual typed Source paths, hashes and lengths and the fixed evidence array from actual Build fields; signed semantic substitutions fail; publisher authenticity remains the Launcher verifier's separate decision.

Publish a later version with --parent PREVIOUS_RELEASE_ID; stage and approve its exact new envelope through F12. Existing instances keep running. Alt-F9/B performs explicit rollback to the retained previous trusted generation. Publishing content does not install it. A published project snapshot has its own named root; an optional explicit --attach-root ROOT_CAP only attaches when the current source head still matches the built revision, otherwise the source remains unchanged and a separate published snapshot is preserved.

Encrypted multi-project retention

./lt vault-init build/objects-v2.img --sectors 24576 --key-out build/objects.key
./lt run --backend qemu --socket /tmp/lt.sock --graphics /tmp/lt.qmp --vault build/objects-v2.img
./lt ctl --socket /tmp/lt.sock vault unlock --key build/objects.key
# Editor F10: inspect name/root/object count/bytes; Enter retains this exact snapshot.
# Explicit management equivalent for selected named roots:
./lt project-vault --socket /tmp/lt.sock save ROOT_CAP OTHER_ROOT_CAP
./lt project-vault --socket /tmp/lt.sock inspect
./lt ctl --socket /tmp/lt.sock vault lock
./lt ctl --socket /tmp/lt.sock shutdown
# Restart with the same explicitly attached image, then:
./lt ctl --socket /tmp/lt.sock vault unlock --key build/objects.key
./lt project-vault --socket /tmp/lt.sock recover

The v2 vault keeps up to six selected named roots and their complete authorized closure, bounded to 64 nodes and 4 MiB aggregate. Immutable temporary roots freeze selection before storage work. Later saves preserve other selected names. Recovery authenticates all members, stages canonical typed records and publishes the complete root set atomically with fresh operational capabilities. Source names, IDs, shared references and selected ancestry survive; app processes, input history, private memory, publisher trust, keys and install approvals do not.

Version 1 development images are not silently reformatted. New v2 extents require a larger explicitly allocated backing; old single-object extents remain distinct. Both write/flush boundaries must complete before durability is acknowledged. Alternating authenticated generations recover an old or new complete snapshot after interruption. There is no whole-store rollback protection without trusted freshness, password KDF, automatic history pruning, physical-drive validation or host-erasure claim. Without a vault the same session workflow is ephemeral.

Actual integrated execution, artifact identities, interruption boundaries and backend limits are recorded in the campaign 003 report and its machine-readable record.

Execution boundaries and remaining gates

Lean supplies the kernel, device policy, compositor, editor, native apps, Objects graph, build-job service, release verifier, vault and cryptography. Assembly implements boot/traps/primitives and the two CPU/device emulators. Host adapters present raw pixels/events and block/entropy bytes. Host Lean/LLVM compile inside an isolated explicit bootstrap job; a separately selected host key signs. No Linux runtime is loaded into native guest applications.
