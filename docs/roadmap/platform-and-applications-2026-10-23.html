Scope. MVP design targets

1. Platform and shared architecture
• Canonical system
   – An open-source, monolingual Lean 4 operating system and native application suite targeting one
     versioned RISC-V machine contract. LemmaTrix is independent of Lemma One hardware; clients, servers
     and clusters share protocols, not identical persistence or resource requirements.
   – Keep guest operating-system code, applications and security policies in Lean. Specify the freestanding
     runtime, compiler backend and machine primitives explicitly: stock Lean native execution includes
                                                                                                                     [1]
     non-Lean components, so ordinary Lean compilation alone does not satisfy this requirement.
• Formally speciﬁed security, not an absolute security promise
   – Require machine-checked proofs of named properties: memory isolation, capability enforcement,
     authorized persistence, signing policy, protocol state transitions and monetary integrity. State each
     theorem's assumptions, protected information, allowed disclosures and excluded channels. Reject
     admitted proofs and undisclosed axioms in release evidence.
   – Connect source-level proofs to shipped binaries through veriﬁed compilation or checked translation, and
     publish the remaining trusted computing base. Hardware, ﬁrmware, boot code, accelerators and side
                                                                                                           [1] [2]
     channels require explicit treatment; writing an app in Lean does not itself prove it secure.
• ARM and x86/x86-64 editions
   – Distribute the same RISC-V guest with a host-speciﬁc emulator written in pure assembly, as requested.
     Treat this emulator and its host adapters as explicit exceptions to the monolingual guest rule. Different
     host instruction sets require different implementations.
   – Prove or validate guest-instruction, memory, interrupt and device semantics. Assembly is not inherently
     faster or safer. Hosted execution depends on the host OS; bare-metal emulation additionally requires its
     own boot and device-support layer.
• Amnesiac sessions plus a persistent vault
   – Run disposable application and service instances. On personal systems, persist only explicitly approved,
     schema-checked records in an encrypted external-drive vault, divided into Wallet, Messenger and
     Objects. Imports become approved Objects; applications never receive unrestricted vault mounts.
   – Wallet holds spending authority and ﬁnancial records; Messenger holds contacts, conversations and
     approved private-agent memory; Objects holds documents, media, code, models and settings. Separate
     keys and access policies for each domain.
   – Server editions must explicitly retain paid-for objects, mailboxes, databases and ledger state. Use
     authorized persistent object stores with retention policies, not a claim that durable services forget
                                                                                                                       [3]
     everything. Shutdown cannot erase copies already held by hosts, recipients or remote providers.
• Lean-deﬁned conﬁguration and packages
   – Provide a Lean conﬁguration language, dependency locking, isolated builds, immutable package graphs,
     signed caches, atomic generations, rollback and garbage collection. Test build reproducibility
     independently. Preserve full functional parity as a goal, but deﬁne it through a versioned feature
                    [4] [18]
     checklist.

   – Adopt Qubes-style security domains and Whonix-style separation of applications from network access.

     network authority. Isolate devices, parsers, build tools, apps and agents; prohibit ambient root or

• LemmaNET: four explicit transport modes
   – Provide low-latency onion routing for interactive use; delayed, padded mixing for stronger metadata
     protection; encrypted bulk-object transport for media and datasets; and private high-throughput cluster
     links for tightly coupled jobs. Specify the anonymity and trust contract of each mode; bulk encryption
     alone does not hide communicating endpoints.
   – Implement the required Tor protocol surface in Lean and test interoperability. Treat compatibility with
     Tor and a new LemmaNET anonymity design as separate deliverables. Never silently fall back from a
                                                         [7]
     privacy-preserving route to a direct connection.
   – Limit social/library discovery to participating LemmaTrix peers and user-selected federations, as
     previously requested. This is a discovery boundary, not proof that participants are honest or that a
                                   [10]
     hostile state cannot join.
• LemmaCoin and the application contract
   – Keep the independent, permissionless, privacy-native L1 with self-custody, mandatory shielded
     payments, private/public contracts, no secret trusted setup, post-quantum security targets and
     cryptographic agility. Audit the entire cryptographic stack; post-quantum signatures alone do not
     establish post-quantum privacy or proof security. NIST standards address particular primitives, not a
                             [9]
     complete blockchain.
   – Give apps shared typed payment intents, fee ceilings, idempotent retries, escrow, refunds, subscriptions
     and bounded delegation. Use consensus for scarce rights and settlement, not every message or video
     chunk. Federation administrators cannot change monetary consensus.
   – Claims of superiority to Solana, Monero or Cardano remain comparative test requirements: use matched
     hardware, workload, adversary model, decentralization constraints and end-to-end measurements, not
     isolated headline numbers.

2. Consumer applications
• Feed
   – Federated short posts, long-form publishing, newsletters, short video and subscriptions, combining the
     requested Mastodon, Substack and TikTok workﬂows. Support votes, LemmaCoin tips and paid
     memberships.
   – Federations may set disclosed rules and fees, moderate content and offer sandboxed extensions. Provide
     user-chosen ranking, portable accounts/content, blocking and appeals. Keep paid promotion separate
     from reputation; purchased votes are not evidence of truth.
• Library
   – A uniﬁed ﬁlm, television, music, audiobook, ebook, course and video-game library with streaming,
     downloads, synchronization and creator publishing. Target the requested Netﬂix/Spotify/iBooks
     experience and Prowlarr/Radarr/Sonarr-style indexing, tracking and acquisition workﬂows within
     the permitted peer/federation scope.

3. Producer and infrastructure applications
• Server Edition and resource marketplace
   – Separate validator/full-node, proof-generation, compute, storage, retrieval/streaming, seeding, mailbox,
     relay, indexing and update-mirror roles. Operators may combine roles, but keep their keys, permissions,
     economics and failure domains distinct.
   – Offer compute jobs, AI/world-model inference and training, model access, datasets, hosting and storage
     through versioned service contracts. Bind execution claims to program/model and input commitments,
     output, numeric semantics, randomness policy and deadlines. Specify accelerator behavior and allowed
     numerical tolerances.
   – Use zero-knowledge execution proofs where the deﬁned workload supports them at an acceptable cost.
     Distinguish correct execution, private inputs, private model weights and useful output; these are
                                                                                                               [12]
     separate guarantees. A proof that an AI model ran does not prove its answer true.
   – For private outsourced inputs, specify homomorphic encryption, secure multiparty computation or an
     explicitly hardware-trusted mode; zero-knowledge alone is insufﬁcient. Benchmark each mode. Where
     the strict no-provider-trust requirement is not met, mark that workload unsupported rather than calling
                       [12] [13]
     it trustless.
   – Compensate storage, streaming, relay, ISP and satellite operators for contracted, measurable service. A
     machine's mere presence earns no automatic revenue. Distinguish storage audits from actual timely
                                                                                                                      [15]
     retrieval, and reject self-dealing trafﬁc or fake demand as evidence of economic value.
   – For closed-weight models, sell conﬁdential inference access or explicitly licensed weight transfer. A

4. Additional ideas
• Privacy, Identity and Recovery Center — proposed application under Settings
   – A single place to inspect capabilities, compartment identities, network modes, persistent records and
     agent authority. Provide key rotation, device revocation, encrypted vault backup, optional threshold
     recovery, restore drills and selective disclosure. Preserve the three vault domains rather than adding a
     general-purpose persistence escape hatch.
• Governance, Credentials and Disputes — potential, cross-application
   – Shared federation rules, scoped credentials, moderation, appeals, resolver selection and
     conﬂict-of-interest checks for Feed, Library, Commerce, Gig and Markets. Support user migration and
     federation forks. Keep moderation authority separate from custody and consensus; portable credentials
     must not silently create a globally linkable identity.
