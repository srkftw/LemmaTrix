Native Forge over an explicitly selected peer

Forge is a separately packaged Lean/RV64 application. It discovers metadata, freezes an explicitly selected graph closure, transfers real records through the isolated encrypted broker and commits received roots through the Objects transaction importer. A metadata query does not import content. A fetched graph grants no publisher ownership, trust, local execution approval or personal durability.

This development profile has one configured ordered peer relationship per broker and advertises one selected content root at a time. A separately isolated guest Registry implements signed chosen-federation admission and a bounded paginated catalog. Two independently configured policies judge the actual original-publisher-signed material. Metadata possession, actual seed availability, technical compatibility and local execution approval remain separate. There is no mandatory global index.

Native controls

ControlActual action
F1Inspect actual federation/policy, signature state, classification/reason, publisher/source/evidence commitments, precise rights and profile.
F2Trusted project picker: actual names and exact root heads. Select a local project or recovered project.
F3Ask the chosen peer for metadata. Show name, root, record count and aggregate bytes; do not import source or sign anything.
F4Freeze and offer the selected root and its exact permitted dependency/history closure. Future edits and unrelated private objects are outside the offer.
F5Fetch the displayed immutable root. Stream bounded records into a private transaction, check actual bytes and canonical edges, then atomically publish a fresh local root. Send a completion receipt only after that commit.
F6Submit the selected received Release graph to trusted Launcher inspection. The guest reconstructs real code and checks signed content, profile and current local trust before showing approval. Actual signed native application, fork, generation update and explicit rollback journeys are recorded in campaign 004.
F7 / F10Explicitly disclose the selected frozen source to the chosen builder/verifier, wait for actual ingestion/quote / explicitly approve its exact execution contract. See the remote-build guide.
F8 / F9Explicit server-store save / inspect, then recover. Requires a separately granted operator namespace. An ordinary Fetch or Pin does not silently create personal host retention.
F11 / SPublish the exact selected frozen closure to the chosen federation / explicitly subscribe to metadata updates for a verified logical project, publication, federation and peer. A subscription does not fetch, install or retain content.
EscapeCancel pending native transfer/import or remote contract. Keep current published roots usable.

The peer's name is drawn in the application surface, not the trusted approval chrome. The trusted workspace owns project selection and execution approval. Network progress uses actual broker job/import state; it does not mean that device acceptance is graph completion. Forge-v1 advertises streamed-record resume explicitly. Objects checks each complete payload and canonical node ID before a bounded 256-KiB private RAM cache may keep its bytes. Escape aborts the graph stage and sends authenticated cancellation. A fresh authorized peer/session/grant can reuse checked records for the same immutable root; the new complete import validates the closure again. Cache bytes are ephemeral, contain no usable capabilities and do not survive restart. Durable transfer checkpoints and automatic multi-peer routing remain limited.

In the native editor, Ctrl-F creates a real fork with an explicitly entered publisher key ID, exact upstream logical identity/head and a fresh entropy commitment. The source and consumed resources are independently editable. Ctrl-K offers an explicit source-only archival checkpoint with retained origin/provenance commitments and actual reclaim counts. The trusted vault view uses U for masked raw-key unlock and R for actual recovery inventory; numbered choices select roots, Enter recovers only that selection. These operations are distinct from publication and execution.

Versions and remaining boundaries

Device stream profile 1; Network SDK/broker 1; Noise revision 34 profile NNpsk0/25519/ChaChaPoly/SHA256; Forge peer protocol 1; Import-v1; graph schema 1 plus explicitly archival schema 2 and Fork-v1; publication scheme 3 alongside legacy scheme 0; server-store format 1; Forge archive 2; RemoteBuild contract 1. In Forge-v1, message types are metadata request/descriptor, closure request/start, node offer/chunk, complete and receipt. Every frame binds version, transaction and exact root, with sequential node/offset bounds. Node identity, schema, predecessor and payload hash reach the native importer.

Direct bulk encryption does not supply traffic privacy. Interactive onion, delayed padded mixing and private-cluster modes are unavailable and fail closed. Signed peer descriptions and federation admission have separate guest verification paths; explicit metadata subscriptions have bounded backoff.
