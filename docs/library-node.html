Library seed operation

./lt library-node runs the selected signed native LibraryPeer package on the same common platform image as a personal guest. Its operator configuration pins the exact release ID and read/network rights 1025, explicit purpose-2 server backing, selected archive slots and immutable manifest commitments, signed service descriptions, relationship credential paths, byte budgets and lifetimes. It contains no content index, transport session key, capability handle or personal vault key. Credential files remain separate, owner-only setup inputs. Direct encrypted bulk discloses endpoint and relationship metadata.

Populate each selected archive through the native server-content permit/retain operations after authorized acquisition or protocol replication. Retention does not require opening Forge. Each seed retains its own bytes through guest-owned writes to its own selected backing. Never initialize or copy another node's backing to manufacture replication. The metadata-only registry may be a separate guest and needs no media archive.

./lt server-store init /explicit/seed-a.img --content
# Provision the signed service description and separate role-2 relationship
# credentials through the documented ./lt network description/init commands.
# Retain selected content under an explicit server namespace and archive slot.
./lt library-node init /explicit/seed-a.json \
  --package /explicit/library-peer.ltrel --public /explicit/publisher.pub \
  --release-id EXACT_RELEASE_SHA256 --store /explicit/seed-a.img \
  --archive-slot 0 --namespace NAMESPACE_SHA256 \
  --manifest-sha256 SELECTED_MANIFEST_SHA256 --bytes EXACT_BYTE_CEILING \
  --connection-slot 0 --credentials /explicit/relationship.server \
  --description /explicit/relationship.service --budget 16777216 --lifetime 100000
./lt library-node add-archive /explicit/seed-a.json \
  --archive-slot 1 --namespace SECOND_NAMESPACE_SHA256 \
  --manifest-sha256 SECOND_MANIFEST_SHA256 --bytes SECOND_BYTE_CEILING
./lt library-node add-relationship /explicit/seed-a.json \
  --connection-slot 1 --credentials /explicit/second.server \
  --description /explicit/second.service --budget 16777216 --lifetime 100000
./lt library-node run /explicit/seed-a.json --backend qemu \
  --image /explicit/identified-common-guest.bin --socket /tmp/seed-a.sock
# run prints the actual native serving instance; use it for inspection.
./lt library-node inspect /explicit/seed-a.json \
  --socket /tmp/seed-a.sock --instance ACTUAL_NATIVE_INSTANCE
./lt library-node stop --socket /tmp/seed-a.sock
# Restart from that seed's own backing; run obtains fresh grants and recovers.
./lt library-node run /explicit/seed-a.json --backend x86_64 \
  --image /explicit/identified-common-guest.bin --socket /tmp/seed-a.sock

Startup checks the pinned package and signed descriptions again, launches the package using explicit operator approval, issues fresh namespace grants and calls asynchronous native recovery for each selected archive. Only the serving incarnation receives the recovered read scopes. It then configures each selected connection and binds each selected immutable root to a separate authenticated protocol stream. The native package owns readiness, request parsing, range authorization, response generation, bounded deadlines and configured live-scope renewal. A stream identity is derived from the manifest commitment; local read handles are never serialized as stream IDs.

The profile supports four archive slots and four independent relationship slots, at most sixteen root/relationship scopes. Aggregate simultaneously recovered payloads must fit the 6,029,312-byte volatile content capacity. One bounded storage engine serializes recovery/retention transactions and returns busy rather than retargeting an active transaction. Each configured stream has its own approved total byte ceiling and boot-relative live-scope lifetime. A fresh connection requires fresh authentication and grants; recovery preserves the durable remaining budget. Removal revokes future serving. Without explicit scope-renewal authority, expiry requires operator recovery or reconfiguration; budget exhaustion always requires new authority. Inspection distinguishes active, waiting for authentication, offline and terminal error states.

library-node recover CONFIG --socket SOCKET --instance INSTANCE performs the same selected recovery/bootstrap into an explicitly supplied fresh native serving incarnation, useful when a package is started separately. Recovery does not serialize or restore execution approval or old transport authority. Repeated recovery into an already populated bounded instance may report quota; restarting the selected guest clears its volatile content scopes while preserving authorized backing. Stop targets only the explicit management socket, and run refuses an existing socket before creating a guest. These commands do not establish independent-operator validation or physical crash durability.

Indexed backing and recoverable serving policy

The commands above remain the legacy four-archive path. For collections beyond the resident payload pool, provision server-store init STORE --indexed, then populate each selected indexed item through normal authorized native acquisition or migration. Use library-node init ... --indexed with its namespace, slot, exact manifest commitment and byte ceiling, or add-indexed for another item. Sixteen indexed selections and at most sixteen combined root/relationship scopes are bounded metadata; their payloads remain on purpose-2 backing. Startup authenticates each selected committed index and opens fresh read handles without reimporting complete payloads into RAM. A partial selection cannot be advertised as a complete seed.

./lt library-node add-indexed /explicit/seed-a.json \
  --archive-slot 5 --namespace SELECTED_NAMESPACE_SHA256 \
  --manifest-sha256 EXACT_MANIFEST_SHA256 --bytes EXACT_BYTE_CEILING
# Explicitly approve durable policy for a legacy configuration; defaults for
# new configurations are generation1,32 attempts and1000000 work quanta.
./lt library-node provision-policy /explicit/seed-a.json \
  --generation 1 --attempts 32 --quanta 1000000
# Optional explicit live-scope renewal under the same finite durable policy:
./lt library-node provision-policy /explicit/seed-a.json \
  --generation 1 --attempts 32 --quanta 1000000 --renew-scopes
./lt library-node pause /explicit/seed-a.json \
  --socket /tmp/seed-a.sock --instance ACTUAL_NATIVE_INSTANCE
./lt library-node drain /explicit/seed-a.json \
  --socket /tmp/seed-a.sock --instance ACTUAL_NATIVE_INSTANCE
./lt library-node resume /explicit/seed-a.json \
  --socket /tmp/seed-a.sock --instance ACTUAL_NATIVE_INSTANCE
./lt library-node cancel /explicit/seed-a.json \
  --socket /tmp/seed-a.sock --instance ACTUAL_NATIVE_INSTANCE
./lt service-jobs --socket /tmp/seed-a.sock list

The shared native ServiceJobs journal snapshots the exact root, requester relationship, policy generation, selected signed description, mode and finite byte/attempt/work limits for each serving operation. Normal LibraryPeer replies reserve actual verified payload bytes durably before sending. Reboot preserves consumed budgets and requires a fresh owner binding and authenticated network session. A lost socket write is conservatively still reserved; it does not count as client integrity acceptance. The protocol's client checks remain separate evidence. Paused/exhausted or approval-required jobs do not prevent unrelated authorized roots from serving.

Pause and drain stop future work; an already reserved reply can finish. Cancel also revokes the selected future serving scopes. These controls do not promise deletion of another node's copies. Retry does not replenish an exhausted budget. Policies use an explicit finite work-quanta time basis; durable absolute expiry is unsupported. To require another approval after restart, set --await-approval-after-restart when provisioning. Automatic resume is otherwise limited to the remaining approved work/attempt budget. Legacy descriptions retain their old16-MiB transport ceiling; the versioned Library service profile supports explicitly approved budgets up to128 MiB. Neither a new connection nor reboot silently expands a limit.

--renew-scopes explicitly adds automatic_scope_renewal to the retained operator configuration and requires automatic resume. After the exact durable serving job is bound, the adapter enables native renewal for that selected scope. Renewal charges a new finite attempt and a work quantum, preserves the remaining transport and durable byte budgets, retires old live grants and obtains fresh authority. Pause, cancellation, revocation or exhausted limits prevent renewal. Without this opt-in, the configured live-scope deadline still expires. This is a boot-relative transport lifetime; the durable job uses admitted work quanta and does not claim absolute wall-clock validity.

The journal is plaintext intentional operator state on purpose-2 backing, separate from approved encrypted personal policies on purpose-1 backing. Neither content commitments nor recovered records are capabilities. Signed descriptions/receipts remain qualified provider assertions; settlement is unavailable, and this voluntary service earns no currency reward. Independent machines, independent operators, physical crash guarantees and unavailable privacy routing require their own evidence.
