Project Notes

Project Notes is ordinary freestanding Lean application source under examples/project-notes. It imports public Lemma.* clients and the separately released Notes.Schema source dependency. The helper implements the versioned note record, checked UTF-8, revision validation and useful title/body search. Its dependency must be retrieved, verified and locked before compilation. A source-only dependency grants no execution or account authority.

This guide describes implemented controls. The Campaign010 machine record identifies executed artifacts and connected steps separately; source availability or successful compilation alone does not establish publication, installation, recovery or network delivery.

./lt sdk check examples/project-notes
./lt sdk build examples/project-notes --output build/project-notes

The exact lemma.lock.json pins SDK and dependency bytes. The normal isolated build includes the semantic resource templates.txt: schema version 1 followed by the default category 0–2 on a second line. Changing that resource changes new-note organization. The application’s foldSearch declaration controls case folding; a fork can change search behavior and the semantic resource without modifying the OS repository.

Status values are 1 awaiting review, 2 frozen for review, 3 locally committed, 4 service accepted, 5 recipient-confirmed or Feed replication-confirmed, 6 cancelled before commit, 7 failed and 8 outcome uncertain. Only actual native owner/transport evidence advances external outcomes. Cancellation after commit returns uncertainty; it cannot retract an accepted event or ciphertext.

Each owner supports four live request rows and three retained committed operation keys. The latter bind originating release, operation identity, destination and exact payload hash/length to its existing outbox. The protected Feed domain3 or Messenger domain2 record retains those associations only after explicit account retention; it never serializes a process handle, grant generation, IPC token or reusable approval. Fresh recovery and fresh native grant authorization can inspect/reconcile the same committed operation. Exhausting the retained key capacity refuses another commit rather than evicting an uncertain send. Unretained owners remain ephemeral.

Repeating a live request still checks its exact current grant generation and expiration. A revoked binding cannot obtain a successful duplicate response. Messenger consults delivery evidence only for a currently authorized inspection of that caller’s own operation.

Native creator controls

F1 in the native workbench now creates the actual public SDK starter with Main.lean, editable lemma.project.json and the canonical pinned lemma.lock.json. The metadata initially names native-tool; edit it as ordinary project source. The editor supports 24 source/resource members up to 32 KiB each, with paged file listing, horizontal caret following and separate undo/redo buffers. The canonical graph still bounds the total manifest to 32 members.

After freezing and successfully building an exact revision, Ctrl+P delegates that selected project and completed job to the trusted compositor. The native coordinator selects a current project publisher or asynchronously generates one inside Identity, then the normal key-free worker returns inert candidate bytes. The creator needs no publisher key file or separate publisher daemon. Native input remains responsive while the exact candidate is prepared. Alt+F12 can also inspect an already prepared release through the same coordinator. The compositor shows project/version/permissions, release, parent/fork, executable, source, manifest/dependency-lock and evidence commitments. Enter signs only the exact prepared release through a one-use physical gesture; Escape cancels uncommitted work. Left/Right pages through every 512-byte chunk of the exact signed canonical manifest, including license, distribution declaration, SDK/dependency and assurance metadata; the page shows its byte offset/total and immutable source/release commitments. Unsupported font bytes are visibly represented by question marks rather than omitted bytes. Pending signing leaves native input available. Compilation, signing, federation admission, installation and execution remain separate approvals.

Once signed, P creates a separately named immutable published-RELEASE_PREFIX snapshot through the native coordinator. It preserves the actual frozen source predecessor and signed helper/fork edges, leaving later editor work intact. Switch to Forge, use its F2 trusted project picker to select that snapshot, and F11 to submit under the configured federation. Admission, installation and execution retain their own native review. Alt+N selects among already approved routed service profiles; see native terminal selection.

The responsive editor drains at most 128 physical events before painting. Ordinary local typing, backspace and search update only affected text rows and status; note, project and view changes repaint the complete view. This fixes an observed real input-queue overflow without changing typing into a confirmation workflow.
