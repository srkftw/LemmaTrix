The dependency sequence was backed content and generic manifests → immutable collection/job scopes → batched ordinary transfer → durable operator and build integration → actual collection, recovery and verification journeys. Storage and contract operations live in focused guest services/packages; ordinary applications retain their 256-KiB code bound. What a person or operator can use

  • Sixteen indexed item slots per explicitly approved storage purpose, with immutable generations, authenticated direct ranges, partial checkpoints, metadata-only recovery, deletion and reader-aware reclamation. Personal storage is encrypted; purpose-2 operator storage is deliberately plaintext. The old selected vault/archive formats and saves remain separate and readable.
  • Eight independent collection policies and four active Library jobs. Policies select a federation, provider set, format/rights/quality rules, finite bytes, mode and destination. Jobs freeze the relevant generation. F5 edits policies, F6 opens retained inventory, and X opens the selected export portal. A separate destination adapter receives only that immutable read scope.
  • The existing player seeks directly into backed content and buffers honestly on verified partial content. Existing Game, save, mod and signed-update paths are preserved.
  • A headless LibraryOperator package drives the same actual Library jobs into each replica's own backing. Shared ServiceJobs stores finite terms, attempts, resource reservations, checkpoints and terminal results; restart recreates current authority. Operators can provision, run, inspect, pause/drain, cancel and recover selected services.
  • Actual remote compilation retains the exact approved source and generic artifact. A separately configured verifier rebuilds the same source/recipe and compares actual bytes. Qualified fixed-body receipts are signed outside the key-free compiler sandbox and verified in the guest.

Commands and exact authority ownership are in persistent collections, Library nodes, indexed storage and remote build. Typical entry points are ./lt inventory, ./lt library, ./lt library-node acquire-init/acquire, ./lt service-jobs, ./lt remote-build and ./lt retrievability.
