HTML documentation policy

Owner instruction recorded 28 October 2026 · Applies to all future first-party repository documentation

Required format

Write all first-party README-equivalent material, specifications, design documents, plans, guides, changelogs, contributor guidance, and other prose documentation as UTF-8 HTML files with the .html extension. Do not create Markdown documentation such as .md, .markdown, or .mdown; do not substitute another prose markup format.

HTML must be actual HTML, with a doctype, language, character encoding, descriptive title, and suitable document structure. Merely renaming a Markdown file to .html is not a conversion. Escape imported text and preserve code, symbols, requirement identifiers, and attribution.

Keep the repository landing page free of a README panel

Use docs/index.html as the documentation entry point. Do not add a README or README.* file at the repository root or in .github/ or docs/. Use descriptive HTML filenames for README-equivalent guidance instead of relying on a README filename or on GitHub's treatment of a particular extension.

Documentation remains visible in the file tree and available after cloning; it is not meant to be hidden or access-restricted. This policy concerns the automatically displayed landing-page document. No GitHub Pages publication or other hosting is required.

Placement and links

Keep the documentation register at docs/index.html, governing source specifications under docs/specs/, and dated historical or future-facing material under docs/roadmap/. Use relative links so the documentation can be browsed locally. Keep source dates and version numbers explicit.

Source integrity and authority

The 28 October 2026 MVP specification v0.2 is the governing detailed baseline. The release charter is a concise acceptance interpretation; the 23 October application list is the broader roadmap. Do not silently expand MVP scope using an older source or treat proposed requirements as implemented capabilities.

Identify every imported source, its date/version, and any extraction limitations. Keep transcriptions separate from editorial commentary. Preserve requirement IDs and page references. Never reconstruct missing original documents from memory and present them as originals. Where archival source binaries are available, retain them unchanged as source evidence; the HTML rule applies to authored repository documentation, not to altering historical source evidence or executable/configuration formats.

Contributor and agent review

Before committing documentation, check that all new first-party prose is HTML, every local link resolves, source attribution is present, and no automatically displayed README file has been introduced. Tool-required source/configuration files retain their required formats. A tool that insists on a Markdown guidance file does not silently override this policy; record and resolve the conflict before adding that file.

This is a recorded repository convention, not an automated enforcement mechanism. No CI workflow or branch-protection rule is added by this document.
