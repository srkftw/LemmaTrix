Exact snapshot build sandbox

Documentation index · Campaign 003, 29 October 2026. The host compiler remains an explicit bootstrap dependency. This path advances SDK-005, IDE-001/003 and REL-003. It does not establish self-hosting, independent builders or verified source-to-binary correctness.

Authorized input and recipe

tools/build_jobs.py accepts only an exported immutable authorized source closure: at most 128 canonical project-relative members and 4 MiB total. Its build_source_snapshot interface requires the job identity, stable guest source-root identity, module, entry, runtime profile and output destination. A separate snapshot digest binds every portable relative name, byte length and SHA-256 payload digest. The request commitment additionally binds the fixed recipe, selected profile, exact SDK/compiler source digest and toolchain identity. Session capabilities and absolute host source paths are excluded from semantic source identity. The guest must validate the returned job, session, frozen root and profile before attaching a result.

The recipe elaborates supplied Lean modules in dependency order, compiles the approved SDK, runs the Lean-authored RV64 backend, assembles and links with the fixed application startup and profile-specific linker script (entry 0x400000 for profile 1; 0x200000 for profile 2), and returns at most 64 KiB native code for profile 1 or 256 KiB for profile 2. Project files cannot shadow the Guest, Compiler or runtime namespaces. Non-source resource members remain available only within the approved input tree. Lean elaboration, imports, metaprograms and evaluation commands all execute inside the sandbox. There is no publisher-signing operation or key input in this API.

OS boundary

On this Linux development host the launcher creates new user, mount, network and PID namespaces, an empty chroot, read-only input and SDK trees, and read-only mounts for the exact resolved immutable Nix toolchain dependency closure. It does not mount the checkout, home directory, credentials, signer, host temporary directories or host network. Only null, zero and entropy device adapters are present. The environment starts empty and receives only fixed locale, SDK search paths, private HOME/TMPDIR and toolchain PATH values. Capabilities are cleared after setup and gaining new privilege through executables is disabled.

Writable storage is limited to a 128 MiB work tmpfs and a 16 MiB temporary tmpfs. Limits include 16 GiB virtual address space per process, Lean's 4096 MiB managed-memory cap, 60 CPU seconds per process, 8 MiB per file, 128 open descriptors, no core dumps and a 120-second outer wall deadline. Lean reserves substantial virtual address space even for small inputs; the address-space bound is not a physical-memory reservation. Linux's process limit counts tasks by host UID, so the enforced hard UID aggregate limit is the observed task count plus 64, recorded in the result. Other activity under that UID may consume or release this shared allowance; this is not a dedicated cgroup quota. Killing the namespace's initial process removes its descendants. Diagnostics return at most 64 KiB, at most 32 source locations, and a maximum 1 MiB artifact transport.

The current closure resolver requires available nix-store metadata and immutable Nix-store tool binaries matching the pinned versions. The existing setup command supplies the pinned tools. Hosts without usable namespace, mount, chroot or declared closure support return unavailable; they do not fall back to an unsandboxed build. No credentials, private signing key or publisher trust state enters the sandbox. Publisher signing and exact local permission approval remain subsequent separate boundaries.

Results and focused execution

The host recomputes artifact hashes and attaches source member IDs, diagnostic locations, request commitment and toolchain identity. Compiler errors leave the previous usable release intact. These are attributable builder results, not a proof that arbitrary metaprogram-generated native code implements its supplied source. A signed release must retain that distinction.
