Native Library

The Library is a focused native package separate from Forge, the player, the original Crate Workshop game, the metadata Registry and the LibraryPeer headless serving package. Its interface uses the existing compositor, keyboard, Project graph, signed release and generation machinery. Catalog records arrive from another guest's signed Registry. Media payloads arrive through separately authorized seed streams; a Registry can hold metadata alone. The native content service validates indexed chunks in bounded quanta. The native player reads those verified ranges and sends decoded PCM through a distinct audio capability.

This is an initial consumer increment, with a bounded volatile content store and explicit encrypted selected-root checkpoints. It supports precise open PCM audio and one original native game. It does not provide video/books/codecs, anonymous routing, payment settlement, broad REL reconstruction or full Library/MVP acceptance. The executed and outstanding portions are listed separately in Campaign005.

Use an explicitly selected publisher key to sign each independently built binary. Profile2 is required. Library rights1919 are object.read/create/revise/share/revoke/enumerate/export127, display256, input512 and network1024. Player rights4865 are read/display/input/audio. Game rights795 are read/create/share/revoke/display/input. Registry rights2175 are Objects127 and server.store2048. A serving LibraryPeer needs network1024 plus object.read1; a registry-only peer may omit object.read. Headless acquirer rights1151 are Objects127 plus network1024. No application receives audio, server backing or vault access because it is first party.

For example, sign a player with the normal release writer:

./lt release create --binary build/live/apps/player.bin --project native-player --version 1.0.0 --profile 2 \
 --right object.read --right display.surface --right input.focus --right audio.output \

The edition rule makes an actual choice between offered mono/stereo records. Details show rejection reasons. A partially validated root exposes only its checked ranges. Interrupted acquisition and offline recovery

P pauses an acquisition. R opens a trusted checkpoint panel containing the selected title, immutable manifest, verified/full byte counts and Objects scope. It encrypts only checked chunks plus the selected signed collection metadata in one transaction. An unverified partial chunk is omitted. After a restart, unlock the selected Objects vault, freshly approve Library/player and use U then Enter. Complete content can play offline with both providers stopped and no original host input file. A partial recovered root remains read-only and incomplete. Connect current providers and verifier, approve a new G policy, then D/T as appropriate. The native content service allocates a fresh operation/provider/budget grant through315; no old capability, transport key, execution approval or job authority is resumed from disk.

Acquisition chunks are authenticated by ordered index/length proofs against the signed manifest root. A provider switch requests the same immutable manifest, obtains fresh authentication/grants and reuses checked chunks. Cancellation removes unpublished staging; a lost reply is resolved through the operation's queryable terminal result. Retention uses alternating authenticated roots/banks and an explicit flush/commit boundary. A killed write can recover an old or new complete checkpoint; it cannot advertise an incomplete root as complete. Physical media durability and rollback freshness remain outside the demonstrated development mechanism.

The current personal content checkpoint has one selected content/metadata slot per explicitly supplied backing, separate from the selected game-save slot. A successful later content retention replaces that slot's current selection; the alternate bank protects a commit in progress. The selected signed item metadata recovers; watchlist history, monitoring intent and acquisition policy do not persist. Monitoring/acquisition requires a new explicit selection and approval after unlock. It is not yet a general retained multi-item collection database. Server content has four independently selected archive slots. A multi-root personal retention inventory and native selection controls remain required before claiming that broader collection workflow complete.

Games, mod data and approved saves

F4 lists real Game consumer facets. Approve/start the separate LibraryFetch package with rights1151, then O binds it as the bounded game acquisition helper. Select an authorized seed with1/2 and use I. The helper freezes the selected signed admission, authenticates its own request stream and acquires the selected Project closure from that provider. It checks exact node identities and payload commitments in a private Objects import before publication. The trusted compositor then displays the ordinary executable approval. The provider must explicitly select that public graph for role3 serving; media availability alone grants no executable graph access. With no helper bound, I uses the existing trusted Project picker for a locally available exact head. A different graph head cannot substitute for the signed consumer admission. The secure Game19-node129807byte acquisition, physical approval and two-push win passed on a fresh recipient with no preloaded Game root; see the exact evidence status.

After installation, J binds the running game only if the kernel reports the exact selected executable Release ID. Alt-Tab to Crate Workshop and play with arrows/WASD; U undo, R reset,1–4 level selection. Original level1 solves with DD. K in Library requests an ephemeral typed save; L asks the game to load it through a temporary selected read grant. B then Enter explicitly retains the save through a trusted Objects-domain panel. N then Enter recovers a selected retained save; L still validates game/schema/pack compatibility before applying it. A cancelled B and K alone write nothing to the vault.

M in Library asks for a granted Project, then lists its bounded Source resources ending .ltlevels. Up/Down and Enter select actual data; Esc cancels. Only a selected read scope reaches the exact game incarnation. The supplied near-goal pack changes level1 from two pushes to one. The game rejects malformed packs and saves for another exact pack. Exported prior save objects remain recoverable. Mod data does not acquire execution or signing authority.

Generation2 changes the visible palette and preserves supported schema1 saves under the same game/pack identity. Install the actual signed second generation through the package approval. Alt-F9 opens the existing generation controls; select rollback explicitly with B in that trusted interface. Each generation either accepts a compatible selected save or refuses it clearly. Retained saves are separate immutable objects, so rollback cannot silently destroy the only valid save. This original puzzle is separate from the required broad Luanti/Lugaru REL milestones.
