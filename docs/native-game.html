Crate Workshop

Campaign005 introduces an original Lean-authored native box-pushing game. Its four original 8×8 levels have one or two crates, targets, walls and a player. Push every crate onto a target. Arrow keys or W/A/S/D move; U or Backspace undo; R resets the selected level; 1–4 select the supplied levels. P makes an immutable ephemeral save snapshot. M returns from an explicitly imported mod to the original pack. The interface shows the selected level, actual successful move count, completion bits, undo depth, package generation and save status.

The supplied solutions, in movement letters, are DD; W; AWSDDW; and AWSDDDW. A blocked movement leaves the board and move count unchanged. Undo preserves the record that a level was completed. The undo history holds128 successful moves; it refuses a new move when full with an inspectable message. Reset or level selection clears that history. A save preserves current board/progress, not undo history. Every level remains selectable, including solved levels.

CrateGame executes parsing, movement, rendering, input and save creation as freestanding RV64 guest code. CrateModel supplies the exact pure movement transitions. The x86-64/ARM64 assembly interpreters execute the same RV64 bytes; host graphical adapters transport pixels/input. There is no host game engine. Source-level blocked-move preservation is a narrowly assumed source theorem, not a verified compiler or binary claim. This original game does not fulfill the separate Luanti/Lugaru reconstruction obligations.

Typed saves and explicit retention

A save is exactly192bytes, kind2 immutable Objects data. It contains magic0x3156415343544c, schema1, game logical ID32, exact selected pack SHA25632, producer generation1/2, selected level, successful move count, current crates/player, completed-level bit mask and64reserved zero bytes. It contains no capability, transport identity, secret, vault key or execution approval. Bounds and game/pack/schema identity are rechecked before state changes. Malformed/incompatible input leaves current progress and every prior immutable snapshot intact.

Both package generations accept producer1/2 schema1 under the same exact game and pack. A future unknown schema or producer is refused with an explicit compatibility message. Export does not overwrite the prior save: existing snapshots remain immutable and readable by their designated grantees. An incarnation can own at most the ordinary eight Objects records; unchanged state reuses its last snapshot, and quota failure is visible instead of deleting older saves.

P and Library save export create ephemeral data only. An independent selected-save approval through the existing trusted Objects-vault path is needed for encrypted retention. The game never invokes Vault. Restoring a retained save after restart needs a fresh unlock, explicit recovery, fresh package approval and a new scoped read handle; stale save handles and process authority are not restored. The exact matching mod pack must be selected before loading a mod save. Without an authorized vault, no personal save is silently written to disk. Whole-backing rollback freshness and physical external-drive power-loss behavior are not asserted.

With a selected federation and authenticated registry relationship, F4 opens the Games view. Q queries genuine signed consumer records. Select the desired edition and press I. The Library does not receive signing authority or approve execution itself.

J binds the running game only when the kernel reports the exact executable Release ID of the selected consumer record. K asks that game for an immutable ephemeral snapshot; L loads the selected snapshot through a fresh scoped read grant. B opens the trusted selected-save retention panel. It shows the game identity, exact save digest, pack digest, producer generation and Objects domain. Enter explicitly retains that192byte object; Esc cancels. K and an unapproved or cancelled B do not persist progress. N opens a separate trusted recovery panel for the selected game. After Enter, Library receives a fresh selected save grant; L still asks the game to validate exact pack/schema compatibility before loading it.

Fresh personal sessions need a fresh vault unlock, native package approval and game binding. Retention grants no Wallet or Messenger access, public seeding, collection enumeration, vault mount or key. Save recovery does not reinstall or execute the game. The legacy selected-object vault root used by game saves remains separate from streamed media format4 and from server content backing.
