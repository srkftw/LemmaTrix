LemmaNET encrypted stream development profile

Documentation index · Machine ABI · Development · Campaigns 004–005, 29 October 2026.

This page describes shipped code boundaries rather than the full NET release gate. Guest service 6 owns the network device, up to four explicitly configured independent ordered peer relationships in profile 2 (one in legacy profile 1), Noise state, bounded grants and transfer jobs. The opaque host stream adapter moves bytes between selected numeric endpoints. It has no graph, catalog, publication, admission or signing semantics.

Campaign 005: optional four-relationship transport profile 2

The network broker now accepts an explicit version-2 envelope, version = 2 | (slot << 8), with slots 0–3. Each bounded relationship owns its selected public description, ordered PSK pins, Noise keys and counters, grants, jobs, inbox, budgets, deadlines, frame suffixes and failure reason. The broker serializes a quantum by loading and saving a private context; it does not yield or issue IPC while a context is active. Four 64-KiB context banks occupy 0x650000..0x68ffff inside its existing 2-MiB arena. Cryptographic scratch is reused only between complete non-yielding operations. Revoking or losing one relationship does not revoke another. Version 1 retains the direct single-stream interface; once version 2 is selected, version-1 requests fail rather than accidentally targeting another relationship.

./lt run --backend qemu --socket /tmp/personal.sock --network-mux selects the opaque LT-Transport-v2 adapter. Provision each separately selected signed relationship with ./lt network configure --socket /tmp/personal.sock --credentials /explicit/client.credential --description /explicit/peer.service --slot 0, then ./lt network open --socket /tmp/personal.sock --slot 0. Repeat in slots 1 and 2 for distinct seeds. Role 1 connects at the verified description’s explicit endpoint; role 2 listens there. status --slot N inspects that relationship; remove --slot N removes its ephemeral enrollment and closes it. Provisioning still requires management authority. The public SDK exposes openPeer for already approved signed enrollments, describePeer for public identity/mode/endpoint inspection, inspectPeer, grantPeer, sendPeer, receivePeer, pollPeer and cancelPeer; credential provisioning and relationship removal still require trusted management; no new native enrollment approval screen is claimed by this transport increment.

Version-2 authenticated plaintext adds a nonzero 64-bit protocol stream ID and nonzero 64-bit request ID after root, operation and length. The maximum application payload is 704 bytes. A stream ID is an application protocol identifier chosen independently of local capability handles, and is bound to its exact local owner incarnation and operation by a receive grant. Concurrent matching receive grants for the same root/operation/stream are refused. The request ID is returned with the authenticated payload. It supports correlation; applications remain responsible for idempotent effects and duplicate request policy. A transport job completing still means device acceptance, never remote content commit.

Deadlines now use the kernel’s monotonic scheduler tick counter, syscall 110, rather than broker iteration counts. They are local monotonic time, not signed wall time or global revocation freshness. In this development profile each context has four grants, eight send jobs and four received records. Four contexts and bounded copying add memory/CPU overhead; this is not a claim of real-time throughput. The adapter has a 64-KiB bound per socket direction and a five-second connect deadline. A failed connection is visible and requires an explicit new open and new authorization; it is not silently reconnected with old authority.

Native Library peer service

Guest.LibraryPeer is a separate headless Lean package, not a host catalog server or an enlarged Forge executable. Its signed service descriptions use schema 2, kind 5 library-registry or kind 6 library-seed, with positive encrypted-bulk mode 3 and operation mask 4 (protocol operation 2). Existing kinds 1–4 retain descriptor schema 1. ./lt network description --kind library-registry and --kind library-seed create these explicitly selected public descriptions. The same signature verification and ordered Noise prologue bind the selection.

The native LibraryPeerSDK uses a 64-byte request and responses with a 64-byte protocol header plus at most 640 bytes. Request words are magic 0x31524545504c544c, version 1, operation, handle/index/offset, argument A, argument B, and two reserved zeros. Remote “handle” here is a snapshot ID or numeric index, never a local capability. The authenticated Network request ID is copied into response word 4 and checked by the client against both the Network envelope and the protocol header. Other response words are magic, version, operation, status, total length, result/snapshot/state and next cursor/availability. The SDK validates this envelope; consumers must additionally verify federation/publisher signatures and immutable commitments before admitting records.

Operation 1 queries the actual bound Registry SDK at a bounded cursor. A consumer-eligible entry snapshots its signed admission descriptor (768 bytes) and original signed ConsumerRelease (768 bytes); the snapshot is private to that relationship. Operation 2 reads bounded slices of that exact snapshot, with a generation ID so a later query cannot silently retarget an earlier read. Non-consumer entries return unavailable with a next cursor. A registry exposes metadata only and need not hold payloads. The granted root must match the admission’s federation identity.

A seed is explicitly configured with one separately shared local Content handle whose canonical manifest hash matches its root grant. Operations 3 and 6 report that selected manifest and measured availability; operation 4 returns the Content service’s authenticated chunk proof; operation 5 reads at most 512 verified bytes within one chunk through scoped Content reads. There is no remote raw backing-sector or arbitrary local-handle operation. Content publication, retention, range permission and integrity remain the Content service’s decisions. Configuration grants a bounded byte budget/lifetime and stream ID per service scope (16 scopes total, at most four per relationship); transport/session loss fails it and fresh authorization is required.

Operator bootstrap is ./lt library-peer --socket SOCKET start --package PACKAGE --public PUBLIC --release-id EXACT_ID, followed by configure --instance INSTANCE --slot N --role registry|seed --credentials RELATIONSHIP --root FEDERATION_OR_MANIFEST_SHA --stream ID; seeds additionally require --content-handle already shared to that exact instance. Repeating configure authorizes multiple selected roots on one relationship, bounded by four grants; the returned scope index is used by inspect. Registry stream ID defaults to 1. Seed stream ID defaults to the first eight manifest-SHA bytes interpreted little-endian, bitwise OR 1; this is derived immutable protocol metadata, never a capability. Explicit overrides must match the client. Removing a transport slot revokes all its scopes. inspect and remove use public IPC through the existing management portal. This bootstrap does not import host media, invent consumer entries or approve personal retention.

Cryptographic profile and identity

The profile is Noise_NNpsk0_25519_ChaChaPoly_SHA256, using the Noise Framework revision 34, 11 July 2018. It implements NNpsk0 tokens, SHA-256/HMAC/HKDF, the RFC 7748 X25519 ladder, and the existing RFC 8439 ChaCha20-Poly1305 primitive. The initial transcript includes a 96-byte prologue: ordered client public-identity digest, server public-identity digest, then explicitly pinned service descriptor digest. Those pins and the 32-byte PSK are provisioned together; messages cannot replace them. A new 32-byte guest RNG draw creates each ephemeral private key. The guest rejects all-zero DH output. Both empty handshake payload tags provide relationship key confirmation before application records are accepted.

Each credential file belongs to one ordered client/server pair. Reversing roles requires separate authorized provisioning. This authenticates possession of that pairwise secret; it is not a publicly verifiable peer signature. Original release, publisher and service signatures need their separate validation. No publisher private key enters this broker. NNpsk0's ephemeral DH contributes forward secrecy, subject to endpoint, RNG, compiler and implementation security; this new implementation has focused vectors and interoperability evidence, not a security audit or formal cryptographic proof. Direct encrypted bulk exposes endpoints, timing and sizes. It provides neither anonymity nor post-quantum security.

Noise transport has separate directional keys and monotonically increasing counters, beginning at zero after Split. A record must authenticate before plaintext reaches a caller. An invalid tag closes the session; no plaintext fallback exists. The profile expires a session after 100,000 monotonic kernel scheduler ticks or 220 records in either direction. Rekey uses a fresh complete handshake, never a counter reset under an existing key. Sealed partial output is retained unchanged until accepted by the device. Disconnect/reset discards sealed output, fails pending jobs, clears grants and inboxes, and erases session material. An application needs a fresh grant before reusing independently verified chunks.

Separately signed service selection

PeerDescription-v1 is an explicitly selected public file of 1,024 bytes: RSA2048 public modulus256, canonical descriptor512 and RSA/SHA256 signature256. The descriptor binds the ordered client ID, the server identity SHA256(public modulus), service kind (Forge, registry, builder or verifier), encrypted-bulk mode, supported service operations, frame/budget limits, declared platform image and printable endpoint. Its SHA256 is the Noise service pin. An absent image declaration is unknown; a signed declaration is not remote attestation. The signature authenticates the selected description independently of the online pairwise Noise MAC. It does not prove online possession of the RSA private key.

Administrative broker operations 11 and 12 stage the public modulus/descriptor and verify its signature inside the guest. Staging disconnects and revokes old session jobs/grants. A failed signature leaves the selection unverified and blocks configuration; a later legacy configure cannot downgrade that selection. Configuration must match all three selected client/server/service pins. Grants must use an operation permitted by the selected signed description. Fresh boots may deliberately select the older three-pin provisioning contract; inspection then reports public service signature unknown. Network-role signing credentials are distinct from federation, publisher and wallet credentials.

Common framing and legacy version-1 service authority

Each ordered stream frame has a two-byte little-endian length. Handshake messages are exactly 48 bytes. Encrypted record frames are bounded to 784 bytes; the authenticated plaintext includes root commitment (32 bytes), service operation (one 64-bit word), payload length (one 64-bit word), and at most 720 application bytes. No operational object, project, grant or job handle crosses this wire. Frames have fixed private storage. The receiver rejects invalid lengths before cryptographic work, processes one bounded frame per turn, and stops reading when four inbox slots are full.

The Network SDK uses endpoint 6 and version-1 headers containing eight little-endian 64-bit words: operation, handle, five operation arguments, version. Requests use the existing kernel ABI2 caller-incarnation, actual-rights and reply-token envelope. Network authority is explicit right 1024; display/input rights do not supply it. Management provisioning additionally requires the existing administrative right. Application grants bind owner incarnation, the configured destination peer and service, exact root commitment, service operation 1–16, direction, mode, total bytes, bytes per monotonic scheduler tick, one outstanding send, and expiration. Four grants, eight outgoing jobs and four incoming records are available. These limits are enforced inside the guest. Remote content availability and local disclosure authority remain different judgments.

OperationRequest and effect
1 ConfigureAdministrative. Role 1 client or 2 server; selected client/server/service digests and PSK. Old jobs and authority are revoked. Credentials are never returned.
2 GrantPeer/service/root digests, operation, send/receive directions, byte/rate/lifetime limits. Only mode 3, encrypted bulk, is available.
3 SendOwned grant, selected service operation and at most 720 payload bytes. Returns an asynchronous job immediately.
4 Poll / 5 CancelOwned job. States: queued, sending, device accepted, cancelled, failed. Cancelling a partially transmitted frame resets the stream.
6 ReceiveOwned receive grant. Returns one authenticated record for that exact root/operation, or would-block status 6.
7 Inspect / 8 Revoke / 9 ResetStatus has no secret material. Revocation cancels queued work and releases inbox storage. Administrative reset requires a fresh handshake.

Status codes are 0 success, 1 denied, 2 malformed/version/scope mismatch, 3 stale or unknown owned handle, 4 quota/concurrency exhaustion, 6 would block and 7 unavailable transport mode. Mode constants are 1 interactive onion, 2 delayed padded mix, 3 encrypted bulk and 4 private cluster. The three unavailable modes fail closed. A small Lean theorem checks that the actual availability predicate rejects them.

A completed send job means the device accepted the encrypted frame, not that the peer committed graph content. Forge's authenticated application receipt and native importer transaction determine graph completion. The four-record receive window stops reading when full. Each authenticated record receives a monotonic session sequence, and receive drains the oldest record belonging to the grant; reusing a freed physical slot cannot reorder later records ahead of older occupied slots. Inspection reports the occupied inbox count. The broker never extends an exact root grant to future descendants. Dead caller incarnations, grant expiry and revocation invalidate their pending work. Nonblocking receive and device syscalls plus a one-tick sleeping syscall keep the service from spinning on empty queues.

Replace the three digests with the deliberately selected public identities and service descriptor commitment. init creates fresh PSK bytes in two exclusive, owner-only files and prints only public pins and paths. Copy only the selected role file to its chosen operator by an authorized provisioning channel. The files are explicit operator credentials and are not an Objects Vault. Configuration is ephemeral per guest boot; unattended startup needs deliberately retained and provisioned credentials. There are no ordinary-operation fixture keys.

Legacy single-stream reset and reconnect boundary

The single-port virtio-console development path has an explicit guest reset epoch and bounded partial reads/writes, but its ready flag does not report a remote TCP endpoint connection event. The opaque relay currently reconnects. Continuing counters prevent nonce reuse while the same session survives, and session expiry forces a new handshake; the implementation cannot claim immediate reauthentication on an otherwise invisible remote disconnect. A deliberate network reset revokes grants and forces reauthentication. Automatic authenticated reconnect/resume with an exact transport disconnect event remains required work. No durable broker checkpoint or session-key persistence is implemented; application content checkpoints follow their separate personal/server durability policy.
