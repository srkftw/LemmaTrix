Persistent collections

The native Library now keeps eight independent collection policies and four concurrent acquisition jobs. A job snapshots its collection, selected federation, provider mask, permitted PCM format and declared rights, quality preference, byte ceiling, retention destination and policy generation. Updating or revoking collection B retires B's unfinished work; it does not retarget A's job or reuse A's consent. Completed authorized content has its own lifetime. Provider discovery remains the existing authenticated LibraryPeer protocol and signed consumer/federation admission.

Open F5 for collection policies. Up/Down chooses a policy. G edits its byte ceiling, eligible providers and retention destination; PageUp/PageDown adjusts MiB, 1/2 toggles providers, R selects the encrypted destination, Enter approves and Escape cancels. S toggles monitoring; C revokes future acquisition for that collection. F6 shows retained selections. Existing Add, playback, Game, save, mod and signed update controls remain available. Reasons and job states remain visible in the queue and per-item details.

A retained item can be opened without its original provider or original host input file. The indexed store authenticates a small index and reads requested chunks on demand. Payload size does not reserve an equal RAM allocation. The existing player checks the actual WAVE header, reads verified ranges, seeks into nonresident content and honestly buffers on unavailable partial ranges. Generic artifacts use ContentFormat-v2 format 2; they are never passed off as audio.

Explicit retained scopes

Provision a destination deliberately. Personal purpose 1 requires the approved encrypted vault unlock. Purpose 2 is intentionally plaintext operator backing. Neither is created as an implicit disk cache. The fixed indexed profile needs 5,394,976 sectors; files are sparse when the filesystem supports it. Existing selected-content formats, archives and saves retain their separate regions and migration path.

./lt server-store init /explicit/operator.img --indexed
./lt vault-init /explicit/personal.img --sectors 5394976 --key-out /explicit/personal.key
./lt inventory --socket /tmp/lt.sock permit --kind personal --slot 0 \
  --bytes ITEM_BYTES --recipient EXACT_LIBRARY_INCARNATION \
  --namespace NAMESPACE_SHA256 --manifest MANIFEST_SHA256
./lt library --socket /tmp/lt.sock --instance LIBRARY policy \
  --collection COLLECTION_SHA256 --federation FEDERATION_SHA256 \
  --bytes BYTE_CEILING --providers 6 --retention 1
./lt library --socket /tmp/lt.sock --instance LIBRARY bind-store POLICY_SLOT --permit LIBRARY_OWNED_WRITE_PERMIT
./lt inventory --socket /tmp/lt.sock list --kind personal --namespace NAMESPACE_SHA256 --cursor 0
./lt library --socket /tmp/lt.sock --instance LIBRARY open-item --permit LAUNCHER_OWNED_READ_PERMIT --operation OPERATION

The permit used by bind-store belongs to the exact Library incarnation and authorizes its writes. Issue a separate permit with the same selected namespace/root to the current Launcher incarnation for open-item; Launcher then delegates only the opened read handle to Library. A permit belonging to Library cannot be used as Launcher authority. Enumeration is bounded to one slot per request; advance the slot cursor through 0–15. Opening rechecks the exact namespace, manifest, generation and item length. A retained partial selection also returns its persisted logical operation ID. After fresh approval and a fresh storage permit, the ordinary Library job skips authenticated already-verified chunks and continues that operation. Neither old transport sessions nor old capability numbers are restored.

Selected metadata is bound before initial acquisition. For older operator imports with no embedded selected consumer record, open-item --registry REGISTRY_INCARNATION --cursor CURSOR selects the actual signed consumer/admission row from a separately recovered native Registry catalog. The Library checks its manifest against the opened content. A public catalog is not a personal watchlist and does not acquire possession of the payload.

./lt library --socket /tmp/lt.sock --instance LIBRARY save-policy POLICY_SLOT --vault-slot 0
# After a restart, unlock the selected encrypted vault and approve fresh packages.
./lt library --socket /tmp/lt.sock --instance LIBRARY recover-policy POLICY_SLOT --vault-slot 0
./lt inventory --socket /tmp/lt.sock delete --grant PERMIT

Policy/history records use independent authenticated encrypted slots. Recovery deliberately shows awaiting approval and clears all live grants. It does not establish absolute expiry or restore old process identity. Deletion tombstones the selected item; an already authorized reader retains its immutable generation until release. Reclamation respects these readers and the other complete bank. This is not secure erasure, revocation of other nodes' copies or malicious whole-store rollback detection.

Native selected export

Choose a complete item in Library and press X. This freezes a read scope for that immutable selection. Then choose a new destination through the explicit adapter:

./lt library --socket /tmp/lt.sock --instance LIBRARY export --output /explicit/new-file.wav

The guest receives an opaque destination commitment, never a host path. Only the selected root is delegated to the destination adapter. The adapter creates a new file exclusively, verifies every source range through ContentSDK, flushes it and acknowledges that destination. A failed output is visibly incomplete. The acknowledgement is not independent storage evidence. Add metadata, Pin, Stream, Subscribe, Seed, Fund and export remain distinct; this command grants no unrelated root or arbitrary filesystem access to the application.

Stop future serving

The existing native peer control removes every serving scope on one selected transport relationship. It stops future work on that relationship without promising deletion of copies held elsewhere. Other relationships remain separate.

./lt library-peer --socket /tmp/seed.sock remove --instance PEER_INCARNATION --slot RELATIONSHIP_SLOT_0_TO_3

Recoverable operator acquisition

Guest.LibraryOperator is a focused headless package around the same Library catalog, policy and acquisition functions. It is not another network broker or scheduler. Its approved server.store authority allows only the actual scopes granted by Vault. It binds each selected collection to an immutable ServiceJobs storage request, charges a finite request-payload budget before requesting a missing chunk and publishes a terminal result only after ordinary integrity checks and complete publication. A failed provider can trigger a bounded fresh execution attempt through another approved provider. Reboot and retry do not replenish the durable byte, attempt or work-quanta ceilings.

./lt app --profile 2 --module Guest.LibraryOperator --entry Guest.LibraryOperator.main --name library-operator
./lt app --profile 2 --module Guest.Registry --entry Guest.Registry.main --name registry-current
# Sign these packages through the existing explicit release workflow.
./lt library-node acquire-init /explicit/acquirer.json \
  --package /explicit/operator.ltrel --public /explicit/publisher.pub --release-id OPERATOR_RELEASE \
  --registry-package /explicit/registry.ltrel --registry-release-id REGISTRY_RELEASE \
  --federation-public /explicit/federation.pub --store /explicit/replica.img \
  --registry-credentials /explicit/indexer-client.credential --registry-description /explicit/indexer.service \
  --provider-credentials /explicit/seed-client.credential --provider-description /explicit/seed.service \
  --collection COLLECTION_SHA256 --namespace NAMESPACE_SHA256 --manifest MANIFEST_SHA256 \
  --bytes ITEM_BYTES --request-budget FINITE_REQUEST_BYTES --attempts 16 --quanta 65536
./lt library-node acquire /explicit/acquirer.json --socket /tmp/replica.sock --backend qemu
./lt service-jobs --socket /tmp/replica.sock inspect SLOT

For selected serving nodes, library-node init/provision-policy --renew-scopes separately opts into renewal of boot-relative transport windows within the exact active, automatically resumable finite operator job. Each renewal consumes an attempt and a work quantum; it preserves remaining bytes and cannot renew a paused, cancelled or exhausted job. The default remains no automatic window renewal. This is not durable absolute expiry.

The configuration is the explicit retained operator approval. On start, the adapter approves the exact signed native packages, recreates current namespace and relationship grants, opens any retained partial item and submits the same canonical operation. The native guest owns the queue and all chunk work; the adapter exits its setup connection and waits for the process. A configuration can select up to eight distinct collection targets and provider relationships 1 and 2. This initial profile chooses one exact retained target per collection and a single configured federation catalog. It does not yet discover arbitrary future durable destinations, implement an unbounded catalog or repair a desired replica count across an arbitrary fleet.

Service validity uses explicitly admitted finite work quanta, attempts and bytes, not boot uptime masquerading as absolute wall-clock expiry. Unsupported paid terms and unavailable privacy modes fail closed. Current mode 3 exposes endpoints and traffic patterns. Signed receipts assert provider reservations and qualified outcomes; client integrity acceptance and independent verification remain separate evidence; voluntary zero-price transfers earn no monetary reward.
