Signed consumer metadata and independent admission

ConsumerRelease-v1 is a512byte canonical publisher-signed record followed by a256byte RSA2048/SHA256 PKCS#1v1.5 signature. It is a Source node named consumer.release in the ordinary signed/versioned Project graph. No local handle is encoded. A content item remains metadata until a distinct authorized acquisition makes payload available. A media item receives no executable facet. A Game requires both the separate consumer gate and the existing canonical native Release gate.

ConsumerFormat validates canonical bounds and supported declarations. Claimed quality is not measurement: the player must parse actual validated content and compare decoded channels/rate/bits/frame count before accepting the edition. A signature proves only the chosen publisher signed the record. It does not establish safety, license ownership, trustworthy quality or local execution permission.

Media must also contain the exact256byte content.manifest Source. The Registry hashes it, compares the signed metadata commitment, validates ContentManifest-v1, and checks its immutable content ID and total bytes. A Game must contain the exact selected game.levels Source and a canonical native Release; Registry compares the resource commitment and requires the same publication, publisher and exact executable Release ID. Level resources remain data. Source/resource substitutions invalidate the commitments; a forged consumer signature cannot become a listing.

Explicit federation policy and catalog SDK

Existing policy1portable and policy2restricted retain their prior meanings. Policy3consumer is operator configured with an explicit allowed executable-rights mask bounded to the known13rights (8191). Its policy hash commits that exact mask and rule version. Native games must request a subset; first-party applications get no bypass. Consumer distribution declarations and supported modes are checked separately. Only encrypted bulk mode3 is eligible; unavailable interactive onion/mix/cluster policies cannot be silently substituted.

Admission-v1 stays512bytes plus federation signature256. Legacy zero extension bytes remain valid. Consumer admission additionally commits SHA256 of the entire originally signed768byte consumer record at400–431, facet at432 and format at440;448–511 remain zero. Classification4 means consumer media admitted;5 means native executable and game consumer admitted;3 remains rejected. Existing native classification2 remains separate. Reason7 denotes malformed/missing/mismatched consumer resource;8denotes federation policy without consumer eligibility. No classification grants local execution, retention, seeding or payment authority.

RegistrySDK.consumer(slot) invokes operation20, returning the exact signed768byte consumer record after the64byte reply header only for a current signed positive consumer listing. Revoked/superseded or unavailable entries do not return metadata. Operation21 provides bounded case-insensitive printable-title search with optional media/game filter: cursor at+8, facet0/all,1/media,2/game at+16, query length0–64 at+24, exact query bytes at+64. It returns the same832byte signed admission page and next cursor as the existing operation6; operation20 then returns the exact signed matching consumer metadata. At most16records and64title bytes per record are searched. Query/history bytes remain ephemeral and are absent from catalog snapshots. Existing bounded query pagination and signed admission lookup are unchanged. A remote verifier may possess a signed admission without the associated consumer bytes; operation20 then honestly fails instead of synthesizing a catalog record.

Operation22 and RegistrySDK.current perform a bounded fast check of an exact768byte descriptor plus expected immutable root against already verified cached bytes. They never create trust and perform no RSA work. Unknown descriptors return unavailable; stale bytes return status3 with the newest known signed classification/reason/sequence. Callers must pause acquisition/playback when this check fails or reports rejection. An accepted cached descriptor is current only relative to this verifier’s knowledge; no global freshness, unseen-revocation or remote-clock oracle is claimed.

Intentional registry retention and migration

Registry snapshot format1 (12,800bytes) remains readable. Format2 uses25,088bytes: the prior512byte header and16admission768byte slots, then16original-consumer768byte slots. Signed admission commitments authenticate the consumer bytes. Missing zero consumer slots preserve only the signed admission and remain unavailable through operation20. Recovery checks federation signatures, configured policy/federation identities, sequence bounds and every present consumer hash/structure before exposing catalog state.

A format2 write uses the existing authorized server-store reserve/append/commit transaction. It does not reinterpret backing sectors or overwrite the prior complete root during append. The previous complete snapshot remains available under the server-store commit/recovery contract. Personal collections, query history, subscriptions, saves, transport keys and grants are absent. Live capabilities are not durable catalog authority. No new public service is deployed by these commands.

Explicit publisher/bootstrap commands

# Complete original resource recipe, without gameplay running on the host:
python3 tools/crate_assets.py --check
# Sign an explicitly selected media metadata record:
python3 tools/consumers.py create --facet media --key PUBLISHER.pem \
  --project original-collection --collection COLLECTION_ID --item ITEM_ID \
  --edition EDITION_ID --title 'Original stereo edition' --sequence 1 \
  --resource content.manifest --frames FRAME_COUNT --channels 2 \
  --license-id 1 --output consumer.release
# Import only signed metadata / bounded manifest, no media payload:
python3 tools/consumers.py import --socket /tmp/publisher.sock \
  --record consumer.release --resource content.manifest --name collection-item
# Explicit federation rule and scoped signing worker:
./lt federation --socket /tmp/registry.sock --instance REGISTRY configure \
  --public FEDERATION.pub --policy consumer --allowed-rights 8191
./lt federation --socket /tmp/registry.sock --instance REGISTRY worker \
  --key FEDERATION.pem --policy consumer --allowed-rights 8191

The disclosed publisher bootstrap signs exactly the selected metadata and imports bytes through ordinary guest Objects operations. The scoped federation signer signs only the chosen immutable guest-evaluated decisions matching its explicitly configured key/policy/mask. Neither is a host catalog, collection database, scheduler or consumer admission service. Normal acquisition/provider/collection operation belongs to the native Library.
