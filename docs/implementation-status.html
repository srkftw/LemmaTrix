Implemented development path

The fixed live image boots a Lean supervisor kernel and separate user-mode Launcher, Objects and Objects Vault services. Packages, source and data arrive through a bounded UART framing protocol after boot. The native launcher authenticates the original publisher's RSA signature and project-scoped trust, inspects immutable release metadata, and binds local approval to the exact release/rights. It stages complete candidates before activation; ordinary updates require a newer semantic version and the current parent release, and explicit rollback selects the retained trusted generation. Existing processes retain private code while another generation is activated. No ordinary install silently wraps a publisher release with the public fixture key.

A 12-slot process table supports eight client slots in addition to idle/launcher/services. Full process identities include a random boot nonce and bounded incarnation counter. Kernel-owned queues supply caller identity, rights, reply tokens, bounded copy-in/out, blocking/wakeup, cancellation and timeout. Client death cancels waiters; service restart clears its private arena and invalidates its old grants. User RX code, RW/NX data and guarded bounded stacks are separate. Console output requires the declared bit and is identity-tagged hex, distinct from trusted binary approval input. New trusted input can cancel a pending client RPC without undoing already committed service effects.

The Objects service owns 64 records up to 64 KiB, chunked transactional import/revision, content hashing, lineage, scoped enumeration, limited delegation, named-grant revocation, explicit export and dead-owner collection. Private application memory is never shared with another service. Native Workbench patches arbitrary byte content into new revisions, Inspector reads metadata, and Worker computes byte/line/word statistics and a digest. These are independently launched compartments making real request/reply calls. The source-first REL grammar now travels through these same objects: native semantic editing, explicit export, disclosed host native compilation/signing, then live import without rebuilding the OS. Intentional edits are recorded separately from equivalent reconstruction.

The vault service uses explicitly attached development block images, actual virtio block/RNG drivers, RFC 8439 ChaCha20-Poly1305 and raw key provisioning. One selected committed Objects snapshot is retained per vault root; all other objects, app state, approvals and grants remain ephemeral. Two authenticated banks and two flushed commit roots permit recovery of an old or new complete snapshot after interruption. Wrong keys, altered ciphertext and failed writes do not expose unauthenticated plaintext. Lock clears accessible service keys/buffers; deletion invalidates roots and flushes. Ciphertext and previously disclosed plaintext copies may remain. Wallet/Messenger domains are rejected; no app receives key material or a filesystem mount.
