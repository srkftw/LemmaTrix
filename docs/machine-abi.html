Development machine, runtime and ABI

LT-Dev-RV64IM-Sv39-v1 / LT-U64-v1 / IPC ABI 1 is a bring-up subset, not the frozen release LT-Machine-v1 required by OS-001. It implements single-hart little-endian RV64 integer and M operations, Zicsr privileged accesses and instruction-cache synchronization. The intended instruction semantics follow RV64I 2.1, M 2.0 and privileged architecture 1.12 for the implemented subset. Compressed, atomic, floating-point, vector, multicore, general PMP configurations, external interrupt controllers, block/network/display/input/RNG devices and complete conformance remain absent.

Boot and devices

The tracked runtime/boot.S starts at physical 0x80000000 in M mode, configures permissive PMP, machine timer and delegation, enters the Lean S-mode kernel, then SRET enters U mode. QEMU runs -M virt -m 16M -smp 1 -bios none -cpu rv64; no default OpenSBI or external firmware is used. QEMU's generic RV64 CPU is a superset; compilation and the assembly emulators enforce the smaller development subset. Unsupported emulator operations trap or terminate with a diagnostic, never return a fabricated success.

Emulators increment virtual time per instruction and implement deterministic timer interrupts; QEMU uses its own virtual timer. Results and fault behavior are compared, not interrupt counts or performance. SFENCE.VMA flushes translation state; FENCE.I observes modified code. The assembly interpreters fetch directly from coherent emulated RAM. Single-hart fences have no inter-hart ordering claim.

Freestanding values, stack and effects

Upstream Lean elaborates and optimizes declarations into Lean IR. Compiler/Main.lean traverses actual reachable IR and emits RV64IM assembly. UInt8/16/32/64, USize, Bool, lets, conditionals, calls, joins and self-tail recursion are supported. Scalars occupy 64-bit stack slots and a0..a7 argument registers; a0 is the return, ra is saved, sp is aligned to 16 bytes. Narrow results are masked. Unsigned division by zero follows Lean's zero result (distinct from raw RISC-V DIVU); shifts use the width-specific semantics. Self-tail calls reuse their frame. Other recursion may exhaust the bounded stack and fault. Compartment restart clears its saved registers, user buffer and stack.

No heap allocator, arbitrary structured Lean values, strings, exceptions or GC are implemented. Buffer/record structure lives in checked bounded memory. Unsupported IR types, closures, initializers, heap operations and unapproved externs fail compilation. No imported upstream runtime or libc symbols are linked. The assembly primitives implement loads/stores, ECALL, architectural startup/trap/return and batch finish only. They return an opaque sequencing token; each call's dependencies must reach the final result. @[never_extract] and compiler.extract_closed=false are mandatory. This backend is not verified.

Trusted IPC and resource contract

ECALL has operation in a7 and handle, buffer pointer, length, value in a0..a3; result is a0. The SDK's six-argument primitive marshals this boundary. Errors use 0xffffffffffffffff. The kernel derives process identity from its saved current process, not a user parameter. Buffers must be inside the mapped 4 KiB IPC page and at most 256 bytes. Handles encode a 56-bit generation and an 8-bit slot. Four capability slots per process carry generation, object scope, rights and active status. Rights are read=1, create/revise=2, share/revoke=4. Delegated read requires read and delegation authority; slot replacement and revocation invalidate stale handles. Generation overflow fails before mutation.

Seven records per session, each 512-byte slot with bounded content, parent, type, owner and SHA-256. Source, revised Object and installed Release records are implemented; release metadata goes through the same read/hash/capability path. Package generations and object revisions share this quota. No dynamic process creation, general delegation tree, general-purpose scheduler, interactive shell or graphical launcher exists. The host command family starts native packages; the tracked guest launcher drives the finite update demonstration.

Package bytes

Each capsule is 0x10200 bytes. Header fields are little-endian UInt64: magic 0x31474b50544c, schema 1, machine 1, runtime 1, entry 0x400000, code length, capability mask, generation; offsets 64..95 hold SHA-256(code), offset 96 holds signed-development mode 2, offsets 104..127 must be zero. Code starts at 128 and is at most 65536 aligned bytes. Offset 0x10100 contains the 256-byte RSA signature of the complete 128-byte header, using exponent 65537 and exact EMSA-PKCS1-v1_5/SHA-256. The trust modulus is supplied separately by boot policy. Payload hash, signature, compatibility, quota and authorized rights are checked before modifying active code or generation. The kernel serializes the copy, commits release metadata and then returns to users. Invalid updates leave the previous active code/generation usable; valid rollback reactivates the former image. There is no durable transaction or full power-loss recovery.

SHA-256 follows RFC 6234; RSA encoding follows RFC 8017. Verification is public-key and variable-time; no private-key operation or guest key generation is supplied. This implementation has tests, not a security audit.
