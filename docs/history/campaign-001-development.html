Build and use the executable platform

Development milestone, 28 October 2026. Run commands from the checkout root. Python 3.11 or later orchestrates the Linux host build. Host emulators currently use the Linux syscall ABI; macOS and Windows adapters are not implemented. Guest application, kernel, policy, SHA-256 and RSA verification logic are Lean-authored; there is no Linux guest or upstream C/C++ runtime in the guest.

Pinned tools and ordinary builds

./lt setup
./lt doctor
./lt build
./lt emulators
./lt run --backend qemu
./lt run --backend x86_64
./lt run --backend aarch64
./lt demo
./lt check

setup uses Nix substitution only for missing exact store paths in toolchain.lock.json; it does not change system configuration. Alternatively install the exact pinned versions and supply LT_LEAN, LT_CLANG, LT_LD_LLD, LT_LLVM_OBJCOPY, LT_LLVM_NM, LT_QEMU_SYSTEM_RISCV64, LT_QEMU_AARCH64, and LT_OPENSSL. Exact Nix cache availability on a new machine is not established by the local evidence. Tool versions are checked; ordinary builds never fetch dependencies. Lean/Lake 4.34.1, LLVM 20.1.8, QEMU 11.1.1 and OpenSSL 3.6.3 are pinned. lake build checks the Lean project with the pinned Lake on PATH; ./lt build performs the freestanding link.

build/guest.bin is the shared raw image; build/image.sha256 records its identity. demo rebuilds and runs the integrated guest, ISA, source-change and rejection checks. check additionally runs guest compiler/arithmetic/SHA/RSA and host package checks. Evidence is in build/acceptance.json, build/checks/, build/compiler-check.log and build/signature-check.log. ARM64 execution uses an actual Linux ARM64 assembly executable under qemu-aarch64 on x86-64; it is not native ARM64 performance evidence.

Import and native SDK template

./lt build --text 'a new project input'
./lt build --text-file /absolute/path/to/input.txt
./lt run --backend x86_64
./lt app --module Examples.NativeUtility --name native-utility

Imports are explicit UTF-8 development inputs, at most 256 bytes, embedded into the generated host image. Host input files, build artifacts and printed terminal/test output remain host data. A fresh boot discards derived guest objects, grants and package generations, then imports the original fixture again. No encrypted vault, host erasure or deletion of original inputs is claimed. Do not use private data in retained development logs.

Copy Examples/NativeUtility.lean inside the checkout to develop an app. Keep the Guest.appMain(initial : UInt64) entry for the tracked startup. The SDK handles object read/revision and bounded buffers through actual syscalls. The present ABI is scalar; handles carry runtime type/scope checks rather than a completed collection of distinct static SDK types. All primitives require @[never_extract] and explicit sequencing tokens; the build disables upstream closed-expression extraction. Unsupported heap/string/closure/runtime features fail with diagnostics.

Sign, inspect, export and run a package

./lt package keygen --private build/developer.pem --public build/developer.pub
./lt package create --name native-utility --version 1.0.0   --elf build/native-utility.elf --binary build/native-utility.bin   --source Examples/NativeUtility.lean --source Guest/SDK.lean   --source Guest/Primitives.lean --source lean-toolchain   --source toolchain.lock.json --source Compiler/Main.lean --source runtime/app.S --source runtime/primitives.S --source runtime/app.ld --source tools/driver.py --source tools/packaging.py --source tools/capsule.py --capability object.read   --capability object.create --capability object.revise --capability console.write   --sign-key build/developer.pem --output build/native-utility.ltpkg
./lt package check build/native-utility.ltpkg --allow-development   --trust-key build/developer.pub --approve-cap object.read   --approve-cap object.create --approve-cap object.revise --approve-cap console.write
./lt package export build/native-utility.ltpkg --output build/exported-utility   --allow-development --trust-key build/developer.pub   --approve-cap object.read --approve-cap object.create   --approve-cap object.revise --approve-cap console.write
./lt run --package build/native-utility.ltpkg --allow-development   --trust-key build/developer.pub --approve-cap object.read   --approve-cap object.create --approve-cap object.revise --approve-cap console.write   --text 'inspect this native object' --backend x86_64

Key generation requires OS entropy and refuses existing outputs. Package creation/export also refuse overwriting outputs. The exported source snapshot, manifest, ELF and raw image retain their hashes. Full reconstruction additionally requires the platform checkout with the matching SDK/runtime source; this package format does not yet bind a platform Git revision; export is not an independent builder attestation. The checker validates canonical bounded encoding, source/rights metadata, exact ELF/raw correspondence, static dependency closure, compatibility, signatures and capability approval. Only statically linked dependency-free packages are implemented; unsupported dependency graphs are rejected.

The outer release uses host Ed25519 verification. The explicit development bootstrap converts its approved native image into an RSA-2048 capsule under the publicly distributed development fixture key; the guest independently verifies that capsule and the actual code hash. That second signature does not establish the original maintainer identity inside the guest. Custom package runs disable the scripted peer/update demo and grant only the capsule's declared object rights. All releases remain development-only, without federated admission or production trust.

Source-first REL fixture

./lt rel import --source examples/rel/rotation.py --output build/rel-project   --license CC0-1.0 --authorization 'original local fixture'
./lt rel build build/rel-project --name rel-component --version 1.0.0   --sign-key build/developer.pem --public-key build/developer.pub   --backend qemu --backend x86_64 --text 'Authorized source input'
./lt rel edit build/rel-project --shift 7
./lt rel build build/rel-project --name rel-component --version 1.1.0   --sign-key build/developer.pem --public-key build/developer.pub   --backend x86_64 --backend aarch64 --text 'Authorized source input'
./lt rel check

The restricted Python AST fixture becomes an editable, content-addressed semantic object. Host tooling regenerates Lean, compiles and signs it, imports it through the same package path, and compares actual guest bytes with the authorized source baseline. Modified behavior is explicitly recorded as different. The extractor supports one bounded byte-transform grammar, not arbitrary Python. It is not a native IDE, Creative Suite, Luanti or Lugaru implementation.
