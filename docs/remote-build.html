Guest-authorized remote build contract

Documentation index · Encrypted stream contract · Disclosed compiler sandbox. Campaign 004 implementation, 29 October 2026.

Guest.RemoteBuild is a bounded application protocol over Network SDK operation 2. The provider's Lean application owns quote, explicit approval, expiration, cancellation and job identity. The existing isolated BuildJobs service freezes the approved root, derives its logical identity from the canonical graph and delegates only that snapshot to the disclosed host compiler executor. The executor receives no publisher key, network namespace access or unrelated project files. A build result grants no publication or local execution approval.

Supported contract

Version 1 supports the fixed Main.main Lean-to-RV64 recipe, runtime profile 2, the exact pinned toolchain digest, at most 4 MiB of authorized input closure, CPU 60 seconds, wall time 120 seconds and a 64 KiB returned artifact limit. The existing namespace sandbox limits address space to 16 GiB, writable work to 128 MiB and temporary storage to 16 MiB. The binary-producing objcopy child has an OS-enforced 64 KiB file-size limit; the bounded result parser also checks it. The request digest includes that output limit. The guest checks actual closure size before enqueueing and rejects an unsupported budget, recipe, profile, changed source, logical identity or toolchain.

All terms are voluntary zero-price. Paid service, wallet settlement, escrow, confidential execution and source concealment from the builder are unavailable. Encrypted transport does not hide the uploaded source from the configured builder. Builder and verifier roles have separate deliberately selected identity pins. Same-host namespace isolation is recorded separately from independent hardware or operators.

The requester physically chooses F7 to request a quote and F10 to approve the displayed source/provider and fixed limits. A provider cannot enqueue an execution before the matching approval. Job IDs use a fresh 32-byte broker nonce. The authenticated contract binds job ID, source root, canonical logical Project identity, toolchain, provider role, recipe/profile and limits. Repeated requests for the same completed input/job return the cached result; substituted fields under a live job ID fail. Expiration uses local application turns and does not claim trusted wall-clock freshness.

Actual artifact return and verification

BuildJobs operations 8–10 accept sequential bounded binary chunks only for the completed exact job/service/source/output/toolchain tuple. Objects validates the actual bytes against the returned digest before commit. Repeating a completed commit is idempotent. Operation 11 gives the original requester a fresh read/export capability for the actual artifact. The provider creates an unsigned result Manifest containing the binary and typed Build/Evidence links to the frozen input, and offers that exact result root to the approved requester. Native F5 fetches the result through the same encrypted graph transfer and transactional importer. An asserted digest alone is insufficient to complete this path.

The verifier must execute its own admitted job in a new isolated compiler environment. compare compares the actual resulting artifact bytes and checks equal source/toolchain/recipe/profile plus distinct builder/verifier identities. A mismatch remains a negative result. This provides reproduced-artifact evidence, not a compiler correctness proof, a publicly signed publisher release or automatic native-app admission.

Operator and native commands

./lt remote-build configure --socket /tmp/client.sock --instance CLIENT_FORGE \
  --credentials client.credential --role client --provider-role builder
./lt remote-build configure --socket /tmp/builder.sock --instance BUILDER_FORGE \
  --credentials builder.credential --role builder
./lt remote-build worker --socket /tmp/builder.sock --instance BUILDER_FORGE \
  --output /explicit/operator/build-output
./lt remote-build inspect --socket /tmp/client.sock --instance CLIENT_FORGE

First configure the ordered Noise relationship and normal Forge peer settings. In the current headless path, physical client F7 freezes and explicitly discloses the selected root to that provider through SourceUpload-v1. Wire16 binds a fresh nonce, exact root/logical identity/toolchain, provider role and bounded node/byte counts; only a configured builder/verifier accepts it. Wire17 confirms actual native import and exact locks before the client requests its quote. F10 approves execution. Ordinary F4 metadata does not cause an unattended upload or job. Previously fetched exact validated source can be reused without duplicate import. The older graphical-provider F3/F5 source selection path remains supported. After a successful execution, F5 on the requester retrieves the actual result closure. Escape cancels an active quote/job. To verify, provision a separately configured verifier relationship and guest, use --role verifier there and --provider-role verifier on the requester, and perform the same native flow.

The worker inspects the provider's native approved job and accepts only its exact BuildJobs identity, frozen root, canonical Project ID and toolchain. This is a key-free executor bridge. It does not read an arbitrary host checkout, decide guest admission, sign releases or approve installation. The output directory is explicit operator/bootstrap retention, separate from personal Objects Vault policy.

Current boundaries

The remote job state and result roots are ephemeral unless explicitly retained through the applicable server store. This increment does not promise automatic durable job resumption across guest restart. Cancellation revokes guest job authority and blocks late attachment; an already running disclosed host compiler may continue until its hard resource deadline. Late quotes or results cannot revive terminal cancellation/expiry, and repeated successful receipts must preserve the same artifact and graph commitments. These pure transition guards are used by the packet handler and have a small Lean proof for cancelled/expired states; the proof assumes the packet already names the current authenticated exact request. One selected remote source scope/job is active per Forge instance. Separately signed public service descriptions are available through the network provisioning profile; the computation result itself remains an authenticated relationship assertion rather than a publicly signed provider attestation. Paid/confidential execution, independent operators and hardware, and privacy routing remain separate requirements.
