Live platform commands and native development

Campaign 002, 28 October 2026. Commands run from the repository root on a Linux host. The native text management service and applications execute in the Lean guest. Python transports framed bytes and invokes disclosed host compilers/signers. This is a development profile, not the complete desktop MVP.

Setup, incremental build and long-lived session

./lt setup
./lt doctor
./lt build
# Optional full rebuild from guest sources: ./lt build --clean
./lt emulators
./lt run --backend qemu --socket /tmp/lt.sock
# Other terminals can connect repeatedly to the same running guest:
./lt ctl --socket /tmp/lt.sock ping
./lt ctl --socket /tmp/lt.sock processes
./lt ctl --socket /tmp/lt.sock shutdown

Choose --backend x86_64 for the native x86-64 assembly executable, or --backend aarch64 for the ARM64 assembly executable under qemu-aarch64 on this host. Each loads the same build/live/guest.bin; identity is in build/live/image.sha256. The session has no batch timeout or instruction budget. The socket is explicitly named, mode 0600, one active transport connection at a time, and is removed on exit. The guest owns all application, package, object and vault policy/state. Closing a client connection leaves the guest running. Incomplete UART frames time out and resynchronize. New trusted input cancels a pending launcher-to-client request so inspection/stop remains usable; already committed service operations are not undone. Request identifiers support exact last-response replay and reject conflicting duplicates. ctl cancel abandons package staging. There is no implicit backing disk. Avoid private inputs in development logs.

Lean 4.34.1, LLVM 20.1.8, QEMU 11.1.1 and OpenSSL 3.6.3 remain pinned in toolchain.lock.json. Setup first accepts available pinned tools; otherwise it attempts the recorded Nix store substitutions. Another checkout can supply matching tools through PATH or LT_LEAN, LT_CLANG, LT_LD_LLD, LT_LLVM_OBJCOPY, LT_LLVM_NM, LT_QEMU_SYSTEM_RISCV64, LT_QEMU_AARCH64, LT_OPENSSL. Nix cache availability and independent builders are not established. Ordinary builds never download. Application artifacts live under build/live/apps/ so an app name cannot replace the OS image. Module and artifact content keys include transitive imports, build flags/templates and pinned tool identity, and reuse unchanged dependencies; an application build does not rebuild or alter the OS image.

Explicit publisher provisioning and post-boot installation

./lt release keygen --private build/publisher.pem --public build/publisher.pub
./lt app --module Guest.LiveApps --entry Guest.LiveApps.workbenchMain --name workbench
./lt release create --binary build/live/apps/workbench.bin --project workbench --version 1.0.0 \
  --sign-key build/publisher.pem --source Guest/LiveApps.lean --source Guest/LiveSDK.lean \
  --right object.read --right object.create --right object.revise --right object.share \
  --right object.revoke --right object.enumerate --right object.export \
  --license NOASSERTION --output build/workbench.ltrel
./lt ctl --socket /tmp/lt.sock trust --project workbench --public build/publisher.pub
./lt ctl --socket /tmp/lt.sock inspect build/workbench.ltrel
# Substitute the inspected release_id; 127 is the exact declared object-rights mask:
./lt ctl --socket /tmp/lt.sock approve RELEASE_ID --rights 127
./lt ctl --socket /tmp/lt.sock activate
# Substitute the returned release slot (one-based), then retain the returned full instance:
./lt ctl --socket /tmp/lt.sock start SLOT
./lt ctl --socket /tmp/lt.sock processes

inspect transports the complete candidate into bounded guest staging and asks the guest to authenticate it. Approval names the exact immutable release identity and exact mask. activate revalidates trust and signature before committing. For an already reviewed candidate, ./lt ctl --socket /tmp/lt.sock install build/workbench.ltrel --approve-release RELEASE_ID --rights 127 stages, compares the exact declared identity/mask, and commits through the same guest approval path. Omitting approval only stages and displays metadata. There is no public development key fallback on this path. RSA-2048/SHA-256 publisher signatures are received and verified by the guest, with keys explicitly scoped to a project. Source/manifest/license/evidence roots are signed commitments; the guest does not prove the build chain or independently check every referenced claim. The JSON sidecar remains an exportable host artifact.

Build Inspector and Worker using entries Guest.LiveApps.inspectorMain and Guest.LiveApps.workerMain; sign separate projects inspector and worker with their chosen exact rights. Read-only inspection needs object.read (1); a worker that only computes statistics also needs 1. Provision each project trust explicitly, inspect, approve, activate and start. All three can stay running alongside the services. Code is statically linked: no fabricated runtime dependency resolver is present.

Objects, edits, sharing and export

./lt ctl --socket /tmp/lt.sock import /absolute/path/source.txt --kind 1
./lt ctl --socket /tmp/lt.sock metadata OBJECT_HANDLE
./lt ctl --socket /tmp/lt.sock share OBJECT_HANDLE --to WORKBENCH_INSTANCE --rights 13
# Use the returned recipient grant, not the launcher's handle:
./lt ctl --socket /tmp/lt.sock edit WORKBENCH_INSTANCE WORKBENCH_GRANT \
  --offset 0 --delete 5 --replacement /absolute/path/replacement.txt
./lt ctl --socket /tmp/lt.sock metadata NEW_LAUNCHER_HANDLE
./lt ctl --socket /tmp/lt.sock export NEW_LAUNCHER_HANDLE --output /absolute/path/new-export.txt
./lt ctl --socket /tmp/lt.sock share NEW_LAUNCHER_HANDLE --to INSPECTOR_INSTANCE --rights 1
./lt ctl --socket /tmp/lt.sock app INSPECTOR_INSTANCE --operation 22 --handle INSPECTOR_GRANT
./lt ctl --socket /tmp/lt.sock app WORKER_INSTANCE --operation 21 --handle WORKER_GRANT
./lt ctl --socket /tmp/lt.sock revoke OBJECT_HANDLE --grant WORKBENCH_GRANT
./lt ctl --socket /tmp/lt.sock drop OBJECT_HANDLE

Import/export use sequential chunks of at most 512 bytes, support objects up to 65536 bytes, and verify SHA-256 before publication. An edit streams a new revision and returns a launcher-scoped handle; metadata includes the immutable parent object ID and content hash. Use ctl list, ctl stats and ctl objects-gc to inspect the authorized scope and collect dead-owner objects/grants. Each replacement is at most 512 bytes; the resulting object remains at most 64 KiB. Sharing limits rights to both the sender's grant and the actual recipient instance's approved rights. Revocation removes future service access, not plaintext already copied. Workbench supports arbitrary byte patches; Inspector returns metadata; Worker counts ASCII words/LFs and reports a content digest. Worker input needs its own read grant. These are independent native clients, not host transformations.

Rights are distinct: read 1, create 2, revise 4, share 8, revoke/drop 16, enumerate 32, explicit export 64, console 128. A read recipient can inspect/read content but cannot use the explicit export operation without 64. Disclosure of plaintext inherently permits copying; the export bit is an API authorization boundary, not DRM. Applications cannot call launcher commands; console requires 128 and is escaped into identity-tagged ASCII hex, so application output cannot form a management approval frame. The SDK supplies typed erased handles/buffers/results and effect sequencing, but general Lean heap values, closures, strings and GC remain unsupported.

Independent lifecycle, update and rollback

./lt ctl --socket /tmp/lt.sock stop INSTANCE
./lt ctl --socket /tmp/lt.sock restart INSTANCE --release-slot SLOT
# Build/sign version 1.1.0 separately, with --parent PREVIOUS_RELEASE_ID:
./lt ctl --socket /tmp/lt.sock inspect build/workbench-1.1.ltrel
./lt ctl --socket /tmp/lt.sock approve NEW_RELEASE_ID --rights 127
./lt ctl --socket /tmp/lt.sock activate
./lt ctl --socket /tmp/lt.sock active workbench
./lt ctl --socket /tmp/lt.sock rollback workbench
./lt ctl --socket /tmp/lt.sock revoke-release RELEASE_ID
./lt ctl --socket /tmp/lt.sock untrust PUBLISHER_KEY_ID
./lt ctl --socket /tmp/lt.sock gc
./lt ctl --socket /tmp/lt.sock service-restart OBJECTS_OR_VAULT_INSTANCE

Activation changes the default release for future starts; existing instances keep their private immutable code until explicitly stopped/restarted. Updates bind the current active release as parent. A downgrade is rejected by ordinary activation. Explicit rollback switches to the retained compatible, unrevoked and currently trusted previous release. All candidates, including escalations, require exact fresh approval. Version, release identity, activation transaction generation and process incarnation are separate. Garbage collection drops unreferenced retained code only when no live process executes it. Service restart destroys its volatile state and invalidates its old grants/keys. Object service restart loses ephemeral objects; vault recovery requires a fresh unlock and import. Application death does not cause unrelated updates or rollbacks.

Explicit development vault

./lt vault-init /absolute/path/objects.img --key-out /absolute/path/objects.key
./lt run --backend qemu --socket /tmp/lt-vault.sock --vault /absolute/path/objects.img
./lt ctl --socket /tmp/lt-vault.sock vault unlock --key /absolute/path/objects.key
./lt ctl --socket /tmp/lt-vault.sock vault status
# Approves exactly the selected committed object snapshot:
./lt ctl --socket /tmp/lt-vault.sock vault retain OBJECT_HANDLE
./lt ctl --socket /tmp/lt-vault.sock vault lock
./lt ctl --socket /tmp/lt-vault.sock shutdown
# Restart using the same explicitly attached image, then explicitly unlock/recover:
./lt run --backend qemu --socket /tmp/lt-vault.sock --vault /absolute/path/objects.img
./lt ctl --socket /tmp/lt-vault.sock vault unlock --key /absolute/path/objects.key
./lt ctl --socket /tmp/lt-vault.sock vault recover
./lt ctl --socket /tmp/lt-vault.sock vault delete
./lt ctl --socket /tmp/lt-vault.sock shutdown

vault-init refuses existing paths; it creates an explicitly labeled regular development image and optionally a mode-0600 32-byte raw key from OS entropy. No password KDF or passphrase support is claimed. This bounded format retains one selected object (including metadata and digest) at a time; a later retain transaction replaces that retained root. Other objects, session grants, applications, trust keys and package approvals remain ephemeral. Recovery imports authenticated selected bytes into a fresh session with new identities and no restored old grants. Use --vault-readonly to exercise write failures. Without an attached unlocked vault all normal object/package operations remain usable and ephemeral.

ChaCha20-Poly1305 authenticated encryption, fresh device entropy, two bank/root generations and explicit block flushes provide the documented crash boundary. Wallet and Messenger domains are denied; apps receive no key or mount. Logical deletion invalidates both roots and flushes; ciphertext may remain on media or copies. Lock wipes accessible broker key/plaintext buffers, but it does not erase previously disclosed object copies. To detach, lock then stop the session and omit --vault on restart. Live physical hot-unplug and physical external-drive validation are not implemented. See format, assumptions and failure semantics.
