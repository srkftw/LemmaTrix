Structured native runtime

Documentation index · Campaign 003, 29 October 2026. This bounded constructor runtime advances OS-005 and SDK-001/002; it is not the complete upstream Lean runtime or a compiler correctness result.

Representation and calling convention

The backend keeps the eight RV64 argument registers and one result register. Fixed-width scalars retain their ordinary representation. General supported constructor values cross functions and modules as one aligned 64-bit pointer; nullary values use the immediate word (tag × 2) + 1. A heap constructor has four 64-bit header words: reference count, constructor tag, reference-field count, and payload-byte count. The payload follows the optimized Lean IR layout: reference words, USize words, then scalar bytes. Projections and updates use the scalar width and offset supplied by that IR. Struct/union return lowering, closures, strings, floating point, arbitrary externs and general upstream heap forms remain explicit compiler errors.

Private bounded ownership

Applications using this runtime reserve private RW/NX virtual addresses 0x418000–0x420000, 256 slots of 128 bytes. Each slot holds a 32-byte header and up to 96 payload bytes with at most eight reference fields. The loader clears new private data before entry. Allocation searches free slots, clears the new payload and initializes its header. A constructor takes ownership of its reference arguments. Optimized IR increments, decrements, deletion, sharing tests and reuse are executed; they are not discarded. The Lean-authored runtime recursively releases owned fields, with a maximum destructor depth of 16. Freed slots are reused. Sharing forces a fresh record before an update; exclusive reset/reuse preserves scalar fields while releasing replaced references. There is no permanent per-event or per-revision allocation.

A bad reference, ownership underflow, depth limit or exhausted arena terminates the affected application with an explicit runtime status in the 0x5254xx domain through the existing exit syscall. It does not return a fabricated value. This is bounded fail-stop allocation, not an exception runtime. Ordinary application recursion remains subject to its mapped stack and guard. Service code must reserve this arena before consuming structured objects; old scalar services do not allocate from it.

SDK consumers

Guest.Structured provides multi-field InputEvent, operational ObjectHandle/ProjectHandle/SurfaceHandle, borrowed Bytes, and tagged Checked success/error values. Checked byte operations validate capacity, index and allowed private address ranges; storage is owned by the application and must outlive the borrowed slice. UTF-8 boundary checks prevent slicing through continuation bytes; glyph rendering is a separate desktop concern. The additional private arena at 0x600000–0x800000 requires runtime resource profile 2. Profile 1 retains its old mappings. A source program cannot gain a profile-2 mapping by constructing a Bytes record.

Executed focused check

python3 tests/structured_runtime.py

The generated consumer crosses two application modules, consumes records with UInt8/UInt16/UInt32/UInt64 fields and tagged variants, boxes and unboxes full-width UInt64 option values, checks out-of-range byte access and UTF-8 boundaries, and performs 4096 shared-record update/reclamation cycles in the 256-slot heap. It ran as actual generated RV64 code under QEMU system emulation. This component harness executes in supervisor mode with a private test mapping; it is not evidence of desktop isolation or interactive hardware. Its current generated image and result are recorded in build/structured-runtime/evidence.json.

The compiler, Lean optimizer, assembly primitives, loader mappings, emulator/device implementation and host build tools remain part of the trusted computing base. No new proof claims or axioms accompany this runtime.
